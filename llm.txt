# YumeKit (@waggylabs/yumekit)

A modern, framework-agnostic Web Components UI kit providing 48 production-ready custom HTML elements. Built entirely on native web standards with zero external runtime dependencies.

## Version
0.5.0

## License
MIT

## Installation

```bash
npm install @waggylabs/yumekit
```

## Key Characteristics
- Pure Web Components (Custom Elements v1, Shadow DOM, ElementInternals)
- Zero runtime dependencies
- Full TypeScript support with type declarations
- Tree-shakeable ESM modules
- ARIA-compliant and keyboard-navigable
- Design token system via CSS custom properties
- 22 built-in themes across 11 color families (blue, orange, green, red, teal, yellow, indigo, purple, pink, brown, olive) × dark and light variants
- React JSX type declarations included
- Form-associated components with native HTML form API support
- Security-focused SVG icon sanitization (allowlist-based)

## Entry Points (package.json exports)

- `@waggylabs/yumekit` — full ESM bundle
- `@waggylabs/yumekit/react` — React JSX type declarations
- `@waggylabs/yumekit/components/y-{name}` — individual components
- `@waggylabs/yumekit/icons/all.js` — all pre-built icons
- `@waggylabs/yumekit/icons/registry` — icon registry API
- `@waggylabs/yumekit/styles/{name}.css` — theme CSS files (e.g. `blue-dark.css`, `purple-light.css`, `olive-dark.css`)

CDN (IIFE):
```html
<script src="https://cdn.jsdelivr.net/npm/@waggylabs/yumekit/dist/yumekit.min.js"></script>
```

### Full Import
```javascript
import "@waggylabs/yumekit";
```

```javascript
import "@waggylabs/yumekit/components/y-theme";
```


### y-theme
Theme provider. Wraps your app and injects design tokens as CSS custom properties.

Attributes:
- `theme` — built-in palette name or a URL/path to a custom CSS theme file. Built-in names: `"blue-light"` | `"blue-dark"` | `"orange-light"` | `"orange-dark"` | `"green-light"` | `"green-dark"` | `"red-light"` | `"red-dark"` | `"teal-light"` | `"teal-dark"` | `"yellow-light"` | `"yellow-dark"` | `"indigo-light"` | `"indigo-dark"` | `"purple-light"` | `"purple-dark"` | `"pink-light"` | `"pink-dark"` | `"brown-light"` | `"brown-dark"` | `"olive-light"` | `"olive-dark"`
- `cross-origin` — boolean, enables CORS for remote theme URLs
- `no-default-font` — boolean, skips injecting the default Lexend font from Google Fonts

```html
<y-theme theme="blue-light">
  <!-- app content -->
</y-theme>
```

### y-break
Decorative divider that draws a horizontal or vertical line, optionally broken by centered content.

Tag: `<y-break>`
Attributes:
- `orientation` — `"horizontal"` (default) | `"vertical"`. Vertical breaks need a height from their container (flex/grid parent or explicit height).
- `align` — `"start"` | `"center"` (default) | `"end"` — position of the centered content along the line.
- `variant` — `"solid"` (default) | `"dashed"` | `"dotted"` — line style.
- `label` — string, plain text rendered in the center.
- `icon` — registered icon name rendered in the center (icon then label when both are set).
- `inset` — `"none"` (default) | `"small"` | `"medium"` | `"large"` — padding applied to the outer ends of the line(s).

Slots: default — slotted content takes precedence over `label` / `icon`.
CSS Parts: `line`, `line-start`, `line-end`, `content`.

The host receives `role="separator"`, plus `aria-orientation="vertical"` when vertical (horizontal is the implicit default and is omitted). With no slotted content, label, or icon, a single unbroken line is rendered.

`--component-break-line-style` overrides the `variant` attribute per instance without re-render.

```html
<y-break></y-break>
<y-break label="OR"></y-break>
<y-break icon="star" variant="dashed"></y-break>
<y-break align="start" inset="medium"><y-tag color="primary">New section</y-tag></y-break>
```

### y-date
Date input field with popup calendar. Form-associated.

Tag: `<y-date>`
Attributes:
- `mode` — `"single"` (default) | `"range"`
- `name` — form field name
- `value` — ISO date string, or `"ISO,ISO"` comma-pair for range mode
- `min`, `max` — date constraints (ISO string)
- `format` — display format string. Tokens: `YYYY` `MM` `DD` `HH` `hh` `mm` `ss` `A` `a` (default: `"MM/DD/YYYY"`)
- `placeholder` — placeholder text when no date is selected
- `color` — color scheme for the datepicker (default: `"primary"`)
- `size` — `"small"` | `"medium"` (default) | `"large"`
- `label-position` — `"top"` (default) | `"bottom"`
- `clearable` — boolean, shows a clear (×) button when a value is set
- `disabled` — boolean
- `invalid` — boolean, applies error state
- `show-hours` — boolean, show hour column in time picker
- `show-minutes` — boolean, show minutes column (implies `show-hours`)
- `show-seconds` — boolean, show seconds column (implies `show-minutes`)
- `hour-format` — `"12"` (default) | `"24"`, 12- or 24-hour clock in time picker
- `minute-interval` — step between minute options (default: `5`)
- `second-interval` — step between second options (default: `5`)
- `show-years` — `"true"` (default) | `"false"`, toggles year select in calendar header
- `show-months` — `"true"` (default) | `"false"`, toggles month select in calendar header
- `show-days` — `"true"` (default) | `"false"`, toggles the day grid (use `"false"` for month or year picker)
- `mobile-breakpoint` — viewport width in px below which mobile mode activates (default: `768` or `--component-datepicker-mobile-breakpoint`)
- `native-mobile` — boolean, when set renders native `<input type="date">` elements on mobile instead of the popup datepicker

Events: `change` (detail: `{ value, startDate, endDate, formatted }`)
Methods: `open()`, `close()`, `clear()`
Slots: `label`, `left-icon`

```html
<y-date name="appt" format="MM/DD/YYYY" clearable>
  <span slot="label">Appointment Date</span>
</y-date>

<!-- Date range -->
<y-date name="trip" mode="range">
  <span slot="label">Travel Dates</span>
</y-date>

<!-- Date + time -->
<y-date name="meeting" show-hours format="MM/DD/YYYY hh:mm A">
  <span slot="label">Meeting Time</span>
</y-date>

<!-- Use native inputs on mobile (opt-in) -->
<y-date name="dob" native-mobile clearable>
  <span slot="label">Date of Birth</span>
</y-date>
```

### y-select
Dropdown/multi-select. Form-associated.

Tag: `<y-select>`

Events: `change`

### y-code
Lightweight, dependency-free code block. Renders slotted source text with optional line numbers, a copy-to-clipboard button, a `max-lines` collapse, and an optional filename header. Built-in tokenizer covers **JavaScript** (alias: `js` / `jsx` / `mjs` / `cjs`), **JSON**, and **CSS**; other languages fall back to plain text. Consumers can also pipe the output of an external highlighter (Prism, shiki, etc.) through the sanitized `highlighted` slot — that path wins when both are available. Span markup is sanitized to an allowlist of `<span>` + token class names; emitted classes are Prism-compatible (`token keyword`, `token string`, etc.) so existing Prism stylesheets layer on cleanly.

Tag: `<y-code>`
Attributes:
- `language` — string. Triggers built-in syntax highlighting when set to a supported language (`javascript`, `js`, `jsx`, `mjs`, `cjs`, `json`, `css`); falls back to plain text otherwise. Also used in the `aria-label`. Case-insensitive. Default `"text"`.
- `line-numbers` — boolean. Renders line numbers on the left and makes each line a focusable / clickable target that copies the line text.
- `max-lines` — number. When set, only this many lines render and the block shows a "Show N more lines" toggle.
- `wrap` — boolean. When set, long lines wrap; otherwise the block scrolls horizontally.
- `filename` — string. Renders a header bar containing the filename and the copy button. Empty hides the header.
- `copyable` — defaults to `true`. The copy button is shown by default; pass `copyable="false"` to hide it.
- `disabled` — boolean. Suppresses interactive controls (copy button, line click). Source code still renders.
- `copy-label` — string. Idle text on the copy button. Default `"Copy"`.
- `copied-label` — string. Text shown briefly after a successful copy. Default `"Copied!"`.

Slots:
- (default) — raw source code as plain text. Consumer must HTML-escape `<` and `&`. Common leading whitespace is automatically stripped (so indented authoring like `<y-code>\n    const x = 1;\n</y-code>` renders flush-left).
- `highlighted` — pre-highlighted markup (consumer-provided). Sanitized to allow only `<span>` with class names in the allowlist (Prism / common highlighter tokens: `keyword`, `string`, `comment`, `function`, `number`, `operator`, `punctuation`, `tag`, `attr-name`, `attr-value`, `selector`, `regex`, `boolean`, `constant`, `class-name`, `type`, `builtin`, `variable`, `property`, `namespace`, `token`, `deleted`, `inserted`, `important`, `italic`, `bold`). Other tags and other class names are stripped. Replaces the default-slot rendering when present.
- `header` — extra header content (e.g., a timestamp or status tag) rendered next to the filename.

Events (bubble + composed, non-cancelable):
- `copy` — `{ source, target: "block" | "line", lineIndex? }`. Fires on successful clipboard write.
- `copy-fail` — `{ error }`. Fires when clipboard access is denied or otherwise throws.
- `language-change` — `{ language }`. Fires when `setLanguage()` is called.

Methods: `copyBlock()` → Promise, `copyLine(index)` → Promise, `setLanguage(lang)`.

CSS Parts: `header`, `filename`, `copy-button`, `copy-feedback`, `pre`, `code`, `line`, `line-number`, `expand-toggle`.

Accessibility:
- `<pre>` has `role="region"` with `aria-label="<language> code, <N> lines"`.
- Copy button has `aria-label` and an `aria-live="polite"` label that updates to the `copied-label` on success.
- Each line, when `line-numbers` is set, has `role="button"`, `tabindex="0"`, and `aria-label="Copy line N of M"`; Enter/Space activate.

CSS Custom Properties: `--component-code-bg-color`, `--component-code-text-color`, `--component-code-font-family`, `--component-code-font-size`, `--component-code-line-height`, `--component-code-border-radius`, `--component-code-header-bg-color`, `--component-code-copy-bg-color`, `--component-code-copy-hover-bg-color`, `--component-code-copy-text-color`, `--component-code-line-number-color`, `--component-code-line-number-width`, `--component-code-line-number-font-size`, `--component-code-line-hover-bg`, `--component-code-line-copied-bg`, `--component-code-scrollbar-color`, `--component-code-scrollbar-bg`, plus per-syntax color hooks (`--component-code-keyword-color`, `--component-code-string-color`, `--component-code-comment-color`, `--component-code-function-color`, `--component-code-number-color`, `--component-code-operator-color`) used by the sanitized highlighted-slot markup.

```html
<y-code language="javascript" filename="hello.js" line-numbers>
function hello() {
    return "world";
}
</y-code>

<!-- Pre-highlighted via Prism / shiki -->
<y-code language="javascript">
    <div slot="highlighted"><span class="token keyword">const</span> x = <span class="token number">1</span>;</div>
</y-code>
```

### y-shape
Presentational container that clips its slotted content into a geometric shape via CSS `clip-path`. Useful for avatar masks, decorative panels, and non-rectangular skeleton loaders.

Tag: `<y-shape>`
Attributes:
- `type` — `"rectangle"` (default) | `"circle"` | `"ellipse"` | `"star"` | `"heart"` | `"chat-bubble"` | `"times"` | `"cross"` | `"polygon"`
- `polygon-points` — required when `type="polygon"`. Comma-separated coordinate list (e.g. `"50% 0%, 100% 50%, 50% 100%, 0% 50%"`). Validated against a safe character set.
- `radius` — shape radius for `circle` / `ellipse`, or corner radius for `rectangle` (e.g. `"50%"`, `"12px"`).
- `fit` — `"contain"` (default) | `"cover"` | `"fill"` — `object-fit` applied to slotted `<img>` / `<video>`. `<picture>` is not a replaced element, so `object-fit` does not apply to it; style the inner `<img>` directly if you slot a `<picture>`.
- `preserve-aspect` — boolean; locks the container to a 1:1 aspect ratio.
- `size` — `"small"` | `"medium"` (default) | `"large"` — container size token (matches the size scale used across other components).

Events: `ready` (`detail: { clipPath }`)
Slots: default — content to be clipped (commonly an image, but any element works).
CSS Parts: `host`, `content`.

`--component-shape-clip-path` reflects the computed clip-path expression; override `--component-shape-size`, `--component-shape-background`, or `--component-shape-color` to theme an instance.

```html
<y-shape type="circle">
    <img src="avatar.jpg" alt="" />
</y-shape>
<y-shape type="rectangle" radius="16px" size="large" style="background: var(--primary-content--);"></y-shape>
<y-shape type="polygon" polygon-points="50% 0%, 100% 50%, 50% 100%, 0% 50%"></y-shape>
```

### y-splitter
Two-pane container with a draggable resize handle. The first child becomes the resizable pane; the second fills the remainder. Auto-assigns `slot="pane-1"` and `slot="pane-2"` to the first two non-handle children — additional children are ignored with a console warning.

Tag: `<y-splitter>`
Attributes:
- `orientation` — `"horizontal"` (default, splits left/right) | `"vertical"` (splits top/bottom)
- `split` — number `0.0`–`1.0`, ratio of the first pane (default `0.5`). Reflects the current value while the user drags.
- `min-ratio` — minimum ratio for the first pane (default `0.1`)
- `max-ratio` — maximum ratio for the first pane (default `0.9`)
- `disabled` — boolean, disables drag and keyboard resizing
- `handle-size` — width (horizontal) or height (vertical) of the drag handle in pixels (default `10`)

### y-progress
Progress indicator. Renders as a horizontal bar (default), a circular ring, or a filled pie sector. Supports single-value or multi-value rendering — when a `values` array of 2+ entries is supplied, the bar stacks, the ring shows concentric arcs, and the pie renders multiple slices.

Tag: `<y-progress>`
Attributes:
- `mode` — `"bar"` (default) | `"ring"` | `"pie"`
- `value` — single numeric value. Deprecated when using multi-value rendering — use `values` instead. Falls back when `values` is unset or invalid.
- `values` — JSON array of `{ value, color?, label? }` entries. - `min` — numeric (default `0`)
- `max` — numeric (default `100`)
- `step` — numeric, snaps `percentage` to step boundaries
- `size` — `"small"` | `"medium"` (default) | `"large"` or a raw length (e.g. `"160px"`). Bar thickness in `bar`, diameter in `ring`/`pie`.
- `thickness` — `"small"` | `"medium"` (default) | `"large"` or a raw length. Ring stroke width; ignored in `bar`/`pie`.
- `color` — predefined scheme (default `"primary"`) or any CSS color
- `track-color` — overrides the unfilled track / ring background; falls back to `--base-background-component`

### y-droplist
Drag-and-drop reorderable list with optional cross-list group support, drag handles, swap mode, and clone mode.

Tag: `<y-droplist>`
Attributes:
- `disabled` — boolean. Removes `draggable` from all items, sets `aria-disabled` on the host, and ignores keyboard reorder shortcuts.
- `vertical` — default reorders along the vertical axis. Set `vertical="false"` to reorder horizontally.
- `animation` — settle-animation duration in ms (default `150`). `0` disables. Honors `prefers-reduced-motion: reduce` regardless of value.
- `scroll` — boolean (default `true`). Auto-scrolls the nearest scrollable ancestor (or `window`) when the cursor is within `scroll-sensitivity` pixels of its edge during a drag. Set `scroll="false"` to disable.
- `scroll-sensitivity` — number (px, default `30`). Distance from the scroll-container edge at which auto-scroll engages. Invalid values fall back to `30`.
- `scroll-speed` — number (px/frame, default `10`). Per-frame scroll delta; clamped internally to `30`. Halved automatically when `prefers-reduced-motion: reduce` is active. Invalid values fall back to `10`.
- `revert` — boolean (default `false`). When present, items dropped outside any valid drop target animate back to their original positions using FLIP. `drag:end` fires after the animation completes. Without `revert`, a cancel is silent (item stays put, `drag:end` fires immediately).
- `force-float` — boolean (default `false`). When present, the ghost placeholder is appended to `document.body` with `position: fixed` so it floats above `overflow: hidden` containers and all stacking contexts. Ghost remains `aria-hidden`.
- `delay` — number (ms, default `0`). Delay before a press becomes a drag. The drag starts only if the pointer remains within `touch-start-threshold` pixels for the duration. `0` means the drag starts immediately on `pointerdown` (for touch/pen) or `dragstart` (for mouse with no effective delay).
- `delay-on-touch-only` — boolean (default `false`). When present, `delay` applies only to touch/pen pointer types; mouse presses bypass the delay and fall through to native HTML5 DnD.
- `touch-start-threshold` — number (px, default `0`). Maximum pointer movement allowed during the `delay` window. If the pointer moves further than this before the timer fires, the pending drag is cancelled. `0` disables threshold checking.
- `ghost-class` — CSS class applied to the placeholder shown at the projected drop position. Default `"y-droplist__ghost"`.
- `drag-class` — CSS class applied to the dragged item. Default `"y-droplist__dragging"`.
- `swap-class` — CSS class applied to the active swap target while dragging in swap mode. Default `"y-droplist__swap-target"`.
- `drag-preview` — boolean (default `false`). When present, a cursor-following clone of the dragged item is rendered in `document.body` during the drag. Distinct from the in-list ghost placeholder — both can be active simultaneously.
- `drag-preview-class` — CSS class applied to the preview element. Default `"y-droplist__drag-preview"`.
- `drag-preview-offset` — `"cursor"` (default) | `"center"` | `"top-left"`. Controls where the preview anchors relative to the cursor. `"cursor"` preserves the grab offset captured at drag start; `"center"` centers the preview on the cursor; `"top-left"` pins the cursor to the top-left corner.
- `drag-preview-scale` — number (default `1`). Scale factor applied via `transform: scale()` to the preview element. Use `< 1` for a shrunken card effect.
- `group` — string. Lists with the same `group` name can exchange items via drag-and-drop. Empty / unset means within-list only.
- `pull` — `"true"` (default) | `"clone"` | `"false"`. Controls whether items leave this list. `"true"` moves the item; `"clone"` leaves the original in place and inserts a copy in the destination; `"false"` blocks dragging out.
- `put` — `"true"` (default) | `"false"` | comma-separated group-name list. Controls whether items can be dropped into this list. `"true"` accepts any same-group item; `"false"` rejects all incoming; a group-name list restricts accepted sources to those whose `group` appears in the list.
- `handle` — CSS selector. When set, drags only initiate from elements within each item that match this selector. Empty (default) keeps the whole item draggable. Invalid selectors `console.warn` and fall back to whole-item.
- `prevent-on-filter` — boolean (default `true`). When `handle` is set, calls `preventDefault()` on `pointerdown` events outside the handle to suppress text selection. No-op when `handle` is empty.
- `swap` — boolean. When present, dropping over an item swaps the two items in place rather than inserting between items. Same-list only; cross-list drops fall through to insert mode. Disabled when `clone` is also set (clone wins).
- `invert-swap-element` — boolean (default `true`). In `swap` mode, controls swap-target selection: `true` picks the item the cursor is currently over; `false` picks the item whose midpoint the cursor has crossed.
- `clone` — boolean. When present, drops insert a `cloneNode(true)` copy at the drop position; the original stays at its source index. Composes with `pull="clone"` (which is the cross-list-source equivalent).

Events (bubble + composed):
- `drag:start` — `{ originalEvent, item, list }` — not cancelable.
- `drag:end` — `{ originalEvent, item, list }` — not cancelable. Always fires; `originalEvent` is the native dragend.
- `drag:enter` — `{ originalEvent, item, list, from }` — not cancelable. Fired on the **destination** list when a foreign item first enters its hit area. `from` is the source list. Only fires when the two lists are compatible (same group, pull/put allow).
- `drag:leave` — `{ originalEvent, item, list, to }` — not cancelable. Fired on the **source** list when the dragged item leaves its bounds. `to` is the destination list, or `null` if the cursor left all droplists.
- `drag:preview` — `{ item, preview, list }` — **cancelable**. Fired after the preview element is created and styled but **before** it is appended to `document.body`. Calling `preventDefault()` cancels preview creation for this drag session — the element is discarded and never enters the DOM. Consumers may mutate `detail.preview` to alter content or add classes; mutations apply before insertion. Because the preview is detached when the event fires, do not rely on `getBoundingClientRect()` or `offsetParent` inside the handler.
- `drag:move` — `{ originalEvent, item, list, x, y }` — not cancelable. Throttled to one event per `requestAnimationFrame`. Fires on every `dragover` / `pointermove` while a drag is active. `x` and `y` are the current viewport cursor coordinates.
- `drag:over` — `{ originalEvent, item, list, target }` — not cancelable. Fires only when the cursor transitions to hover a **different** slotted child (`target`) than on the previous tick. Does not re-fire when the cursor stays over the same item.
- `drag:drop` — `{ originalEvent, item, list, index }` — not cancelable. Fires **before** the DOM mutation on a successful drop. `index` is the projected insertion index (0-based).
- `reorder` — `{ oldIndex, newIndex, item, list[, from] }` — not cancelable. Fires only when index changes. On a cross-list drop `oldIndex` is `-1` and `from` is the source list. On a `swap` drop, `oldIndex` and `newIndex` describe the two swapped items. On a same-list `clone` drop, `oldIndex` is `-1` and `item` is the inserted clone.
- `update` — `{ item, oldIndex, newIndex, list[, from] }` — not cancelable. Fires immediately after `reorder`. On a cross-list drop the **source** fires first with `newIndex: -1`; the destination fires next with the insert position. On a same-list `clone` drop only the destination event fires (source is suppressed).

Methods:
- `toArray()` — returns each direct child's `data-id` (or `""` if missing) in current DOM order.
- `hasItem(item)` — true when `item` is a direct slotted child of the droplist.
- `destroy()` — removes all listeners, the mutation observer, and unregisters from the cross-list group registry. The component re-initializes on disconnect/reconnect.
- `sort(compareFn?)` — sorts all slotted children in place. The default comparator compares each child's `data-id` using `<` / `>` semantics (plain lexicographic/ASCII-style ordering, not `localeCompare`). Fires a single `update` event with `{ oldIndex: -1, newIndex: -1 }`. Pass a custom `(a, b) => number` comparator for custom order.
- `option(name, value?)` — get or set the component property corresponding to a kebab-case option name (mapped to camelCase). One argument returns the current property value; two arguments assigns that property. Depending on the property, this may return non-string values and may reflect to, update, or remove the underlying attribute.
- `closest(evt)` — returns the direct slotted child whose bounding rect contains `evt.clientX`/`evt.clientY`, or `null` if none match.

Behavior:
- Items get `role="listitem"`, `tabindex="0"`, `draggable="true"`, and `aria-grabbed="false"` automatically; new children added at runtime are auto-initialized via `MutationObserver`.
- Keyboard reorder: focus an item, press `ArrowUp`/`ArrowDown` (or `ArrowLeft`/`ArrowRight` when `vertical="false"`). Focus stays on the moved item; `reorder` and `update` fire identically to a mouse drop. When `handle` is set, focus may be on the handle element; keydown still works via bubbling and focus stays on the handle.
- A polite `aria-live` region inside the shadow root announces moves. Within-list: _"Item moved from position X to position Y."_ Cross-list: _"Item moved to list `<aria-label>` at position N."_, falling back to _"another list"_ when the destination has no accessible name. Swap mode: _"Item swapped with position N."_ Clone: _"Item copied to position N."_ (or _"Item copied to list `<label>` at position N."_ for cross-list).
- Settle animation uses FLIP. Skipped when `animation="0"` or `prefers-reduced-motion: reduce`. Swap mode skips FLIP since the two affected items jump directly.
- Cross-list compatibility is checked on every `dragover`. Incompatible combinations do not call `preventDefault()`, so the OS shows the "not allowed" cursor and no ghost appears.
- `handle` mode: items get `tabindex="-1"` and the first matching descendant element gets `tabindex="0"` (only when the descendant doesn't already have a tabindex). On `pointerdown` outside the handle, `draggable` is flipped to `false` until `pointerup` / `pointercancel`, blocking the native drag from starting.
- `clone` overrides `swap` when both are set on the same list — the drop performs a clone insert and the swap indicator never appears.
- **Touch / pointer pipeline**: Touch and pen input uses `pointerdown` / `pointermove` / `pointerup` with `setPointerCapture`. `touch-action: none` is applied to the press target (the item, or the handle element when `handle` is set) at decoration time — before any touch begins — so mobile browsers do not preempt the press as a scroll gesture. It is cleared only when the list is disabled or the handle selector changes. Mouse presses with no effective delay defer to native HTML5 DnD. Cross-list touch drops use bounding-box hit-testing via `getBoundingClientRect`. `originalEvent` in `drag:start` / `drag:end` is the originating `PointerEvent` for touch drags. Supported: iOS Safari 14+, Chrome Android 90+, desktop Chromium / Firefox / Safari latest two majors.
- Auto-scroll uses a shared `requestAnimationFrame` loop (one loop across all `<y-droplist>` instances). The scroll container is found by walking up from the hovered list via `getComputedStyle(...).overflow` and is cached per-drag on the source list. Scrolling stops on `dragend`.
- `revert` shares `--component-droplist-transition-duration` / `--component-droplist-transition-easing` with the settle animation. With `prefers-reduced-motion: reduce`, the items snap back without easing and `drag:end` fires immediately.
- `force-float` ghost inlines its own styles (background/border/opacity via CSS custom properties that cascade from `:root`). The `::slotted([data-y-droplist-ghost])` shadow rule does not apply to it. The insertion position is tracked internally per-drop so the item is inserted at the correct index on drop.

Slots: default (slotted items). `drag-preview` — optional; when present, the slotted element is deep-cloned and used as the preview content instead of cloning the dragged item. The original is hidden during the drag and restored on drop.

CSS Parts: `list` (the shadow-DOM wrapper around the slot). The drag preview element carries `part="drag-preview"` but is appended to `document.body` (outside the shadow root), so `::part(drag-preview)` cannot match it — see "Styling the drag preview" below for workable selectors.

Styling items: list items are slotted light-DOM children, so style them with regular descendant selectors (`y-droplist > *`, `y-droplist > .y-droplist__dragging`, etc.) — `::part()` doesn't reach light DOM.

Ghost vs. preview: the ghost (`[data-y-droplist-ghost]`) is the in-list dashed placeholder that shows where the item will land. The drag preview (enabled via the `drag-preview` attribute) is the cursor-following visual clone rendered in `document.body`. Both can be active simultaneously. Safari may show its native drag image alongside the custom preview because it ignores `setDragImage` — a known Safari limitation.

Styling the ghost placeholder: target it via the `[data-y-droplist-ghost]` attribute selector, the class set by the `ghost-class` attribute (default `.y-droplist__ghost`), or the `--component-droplist-ghost-*` custom properties below.

Styling the drag preview: target the class set by `drag-preview-class` (default `.y-droplist__drag-preview`), the `[part="drag-preview"]` attribute selector, or the `--component-droplist-drag-preview-*` custom properties. Note: `::part(drag-preview)` does **not** work because the preview is rendered in `document.body`, not inside the shadow root — use the class or attribute selector instead.

CSS Custom Properties: `--component-droplist-ghost-opacity`, `--component-droplist-ghost-background`, `--component-droplist-ghost-border-color`, `--component-droplist-item-padding`, `--component-droplist-item-margin`, `--component-droplist-transition-duration` (override the `animation` attribute), `--component-droplist-transition-easing`, `--component-droplist-swap-indicator-background` (background applied to the active swap target), `--component-droplist-handle-color` and `--component-droplist-handle-size` (convenience tokens consumers can use to style their own handle elements; not used internally), `--component-droplist-drag-preview-opacity` (default `0.85`), `--component-droplist-drag-preview-shadow` (defaults to the theme-wide `--base-shadow` when unset; if `--base-shadow` is also unset, falls back to the hard-coded `0 4px 12px rgba(0,0,0,0.15)`), `--component-droplist-drag-preview-rotate` (default `0deg`; set e.g. `2deg` for a tilt), `--component-droplist-drag-preview-cursor-offset-x` / `--component-droplist-drag-preview-cursor-offset-y` (additive px offsets from the cursor anchor), `--component-droplist-drag-preview-z-index` (default `9999`).

### y-grid

Attributes:

- `rows` — integer or raw `grid-template-rows` value (default unset → implicit rows)

### y-masonry
Layout container that packs children of varying heights into the shortest column via JS positioning. Use `y-grid` for uniform CSS-Grid layouts.

Tag: `<y-masonry>`
Attributes:
- `columns` — integer column count (default `3`)
- `gap` — `"none"` | `"x-small"` | `"small"` | `"medium"` (default) | `"large"` | `"x-large"` | `"2x-large"` | `"4x-large"` — maps to `--spacing-*` tokens

Methods: `relayout()` — force an immediate repack (useful when item heights change in ways `ResizeObserver` won't catch synchronously, e.g. after an image loads).

CSS Parts: `container`

A11y: layout-only (no role, no aria). Tab order follows DOM order — visual order may diverge from focus order.

### y-paginator
Page navigation control with configurable button window, ellipsis collapsing, prev/next, an optional items-per-page select, and SPA-friendly cancelable events. Page buttons are rendered as `y-button` (flat for inactive, filled primary for the active page).

Tag: `<y-paginator>`
Attributes:
- `current-page` — currently active page (1-indexed). Clamped to `[1, total-pages]` when `total-pages >= 1`, and reports `0` when `total-pages = 0` (no-data state). Default `1` (or `0` when there is no data).
- `total-pages` — total number of pages. `0` indicates no data; in that state the page list is omitted and `current-page` reads as `0`. Default `0`.
- `page-count` — maximum page buttons displayed at once, excluding ellipses. Default `5`. The rendered count auto-shrinks to fit narrower host widths and grows back up to this maximum as space allows.
- `boundary-count` — number of pages always shown at each end. Default `1`.
- `variant` — `"default"` (default — page-number buttons with prev/next), `"compact"` (first / prev / "n of n pages" status / next / last; no page list), or `"detailed"` (default layout plus prev/next text labels).
- `size` — `"small"` | `"medium"` (default) | `"large"`. Forwarded to the page `y-button`s and the items-per-page `y-select`.
- `disabled` — boolean. Disables every interactive control.
- `hide-on-single-page` — defaults to `true`. The component hides itself when `total-pages <= 1` *and* there is no items-per-page select to show. Pass `hide-on-single-page="false"` to always render.
- `items-per-page` — currently selected items-per-page value (number).
- `page-size-options` — JSON array of numbers (`[10, 25, 50]`) or `[{value, label}]` objects. When set, an items-per-page `<y-select>` is appended after the navigation wrapper (i.e., to the right of the page list, wrapping below on narrow widths).
- `page-size-label` — label text shown next to the select; only visually rendered when `variant="detailed"`, otherwise applied as the select's `aria-label`. Default `"Items per page:"`.

Events (cancelable, bubble + composed):
- `page-change` — `{ page }`. Calling `preventDefault()` aborts the page transition.
- `update:current-page` — `{ page }`. Fires after `page-change` for two-way-binding consumers; cancelling it also aborts.
- `page-size-change` — `{ pageSize, previous }`. Cancellation reverts the select to the prior value.
- `update:items-per-page` — `{ pageSize, previous }`. Mirror event for v-model-style consumers.

Methods: `goTo(page)`, `next()`, `previous()`, `setPageSize(value)`.

Slots: `prev-label`, `next-label` (override the prev/next button content; only rendered when `variant="detailed"`), `ellipsis` (override the `…` glyph).

CSS Parts: `wrapper`, `nav-wrapper`, `list`, `button`, `button--active`, `button--disabled`, `nav-first`, `nav-prev`, `nav-next`, `nav-last`, `compact-status`, `ellipsis`, `page-size`, `page-size-label`, `page-size-select`. (`nav-first` / `nav-last` / `compact-status` only appear when `variant="compact"`.)

Keyboard: while focus is on a page `y-button`, `ArrowLeft` / `ArrowRight` step focus between buttons and `Home` / `End` jump to the first / last interactive button.

```html
<y-paginator total-pages="50" current-page="5"></y-paginator>

<y-paginator
    total-pages="100"
    current-page="42"
    boundary-count="2"
    variant="detailed"
    items-per-page="25"
    page-size-options="[10, 25, 50, 100]"
></y-paginator>
```

### y-tree
Hierarchical navigation tree for sidebars, doc nav, and file/folder explorers. Use when leaf nodes are navigation targets (links). For collapsible content regions, use `y-panelbar` / `y-panel`.

Tag: `<y-tree>`
Attributes:
- `exclusive` — boolean. Expanding one branch collapses sibling branches at the same level.
- `selection` — `"single"` (default) | `"none"`. Whether one item can be selected at a time, or selection is route-driven only.
- `route-match` — `"exact"` (default) | `"prefix"` | `"off"`. How `href` matches against `window.location.pathname`. `"prefix"` highlights ancestor items when a descendant route is active.
- `aria-label` — defaults to `"Tree"` if omitted.

Methods: `getAllItems()`, `getVisibleItems()`, `focusItem(item)`

Events bubble from items: `navigate` (cancelable, `{ href, item }`), `select` (`{ item, href }`), `expand` (`{ item }`), `collapse` (`{ item }`), `toggle` (`{ item, expanded }`).

Slots: default — one or more `<y-tree-item>` elements forming the root level.

CSS Parts: `tree`

### y-tree-item
Individual node in a `y-tree`.

Tag: `<y-tree-item>`
Attributes:

- `selected` — boolean. Active/current state. Auto-managed by the tree when `route-match` is on.
- `disabled` — boolean. Non-interactive and skipped in keyboard navigation.
- `history` — `"push"` (default) | `"replace"` | `"false"`. History API behavior on navigate. `"false"` performs a full-page nav.

Methods: `expand()`, `collapse()`, `toggle()`, `activate()`

### y-animate
Lightweight wrapper that applies a preset CSS-based entrance/exit animation to its children using the Web Animations API. Useful for adding visual polish to list items, modals, cards, or anything that enters / leaves the DOM.

Tag: `<y-animate>`
Attributes:
- `animation` — preset name: `"fade"` (default) | `"slide"` | `"zoom-in"` | `"zoom-out"` | `"flip-horizontal"` | `"flip-vertical"` | `"rotate-in"` | `"bounce"` | `"shake"` | `"scale"`
- `direction` — `"up"` (default) | `"down"` | `"left"` | `"right"`. Used by `slide`, `bounce`, and `shake`; ignored by `flip-*`, `zoom-*`, and `rotate-in`.
- `duration` — animation duration in ms (default `300`)
- `delay` — delay before the animation starts in ms (default `0`)
- `easing` — CSS easing keyword, `cubic-bezier(...)`, or `steps(...)` (default `"ease-out"`)
- `trigger` — `"load"` (default, plays on connect) | `"visible"` (plays when scrolled into view via `IntersectionObserver`) | `"manual"` (only via `play()`)
- `once` — `"true"` (default) | `"false"`. When false, visibility-based triggers re-fire on each entry.
- `reverse` — boolean, plays the animation in reverse
- `stagger` — boolean, animates each direct child individually with a per-index delay
- `stagger-delay` — per-child delay in ms when `stagger` is set (default `50`)
- `disabled` — boolean, blocks playback entirely
- `hidden` — standard HTML attribute; cancels any in-flight animation and hides the host

Events (bubble + composed, not cancelable):
- `animation-start` — `{ animation, element }` — fired when each animation begins
- `animation-end` — `{ animation, element }` — fired when each animation completes
- `animation-cancel` — `{ animation, element }` — fired when `abort()` is called or the host is hidden / disabled mid-flight

Methods:
- `play()` — manually triggers the animation. Returns `Promise<void>` that resolves once all animations finish.
- `reset()` — clears `hasPlayed` state and inline styles applied by stagger targets
- `abort()` — cancels any currently running animations and emits `animation-cancel`
- `setAnimation(name, duration?, easing?)` — convenience setter that updates the matching attributes

Slots: default — children to animate.
CSS Parts: `content` — the wrapper around the children.

Accessibility: respects `prefers-reduced-motion: reduce` — animations are skipped, but `animation-start` / `animation-end` still fire so consumers can sequence dependent UI.

CSS Custom Properties:
`--component-animate-duration` (default `300`), `--component-animate-stagger-delay` (default `50`), `--component-animate-fade-opacity-start` (default `0`), `--component-animate-fade-opacity-end` (default `1`), `--component-animate-slide-distance` (default `16px`), `--component-animate-zoom-in-scale-start` (default `0.8`), `--component-animate-zoom-out-scale-start` (default `1.2`), `--component-animate-rotate-angle` (default `90`), `--component-animate-bounce-height` (default `16px`), `--component-animate-shake-amplitude` (default `8px`), `--component-animate-scale-start` (default `0.5`), `--component-animate-scale-end` (default `1`).

```html
<!-- Fade in on mount -->
<y-animate animation="fade" duration="400">
  <y-card>Hello</y-card>
</y-animate>

<!-- Stagger a list when it scrolls into view -->
<y-animate trigger="visible" animation="slide" direction="up" stagger stagger-delay="80">
  <y-card>One</y-card>
  <y-card>Two</y-card>
  <y-card>Three</y-card>
</y-animate>

<!-- Manual play -->
<y-animate id="bump" trigger="manual" animation="bounce" once="false">
  <y-button>Bump me</y-button>
</y-animate>
<script>
  document.querySelector("#bump y-button").addEventListener("click", () =>
    document.getElementById("bump").play()
  );
</script>
```

## Design Token System (CSS Custom Properties)

Applied by y-theme or by manually including a theme CSS file. Variables follow this naming pattern:

```
--{scheme}-background-app
--{scheme}-background-component
--{scheme}-background-hover
--{scheme}-background-active
--{scheme}-border
--{scheme}-content--
--{scheme}-content-inverse
--{scheme}-content-hover
--{scheme}-content-active
```

Where `{scheme}` is: `base`, `primary`, `secondary`, `success`, `warning`, `error`, `help`

Additional tokens:
```
--spacing-none, --spacing-4x-small, --spacing-2x-small, --spacing-x-small, --spacing-small, --spacing-medium, --spacing-large, --spacing-x-large, --spacing-2x-large, --spacing-4x-large
--font-size-small, --font-size-paragraph, --font-size-label, --font-size-button, --font-size-quote, --font-size-h1…h5, --font-size-display-1…4
--radii-none, --radii-x-small, --radii-small, --radii-medium, --radii-large, --radii-x-large, --radii-full
--font-weight-body (300), --font-weight-heading (500)
--base-shadow
```

### Component tokens

Every component reads tokens named `--component-{component}-{property}` (e.g. `--component-dialog-offset`, `--component-slider-track-color`). Structural/dimension tokens are defined in `tokens/core/components.json`; color tokens are defined per-theme in `tokens/themes/*.json`. Both are compiled by `npm run build:tokens` into `styles/variables.css` (the baseline + default theme) and `styles/{theme}.css` (per-theme overrides) — **`styles/variables.css` is the authoritative full list.** Many component entries in the Component Reference above also enumerate their own tokens on a `CSS Custom Properties:` line.

## Icon Registry API

```javascript
import { registerIcon, registerIcons, getIcon } from "@waggylabs/yumekit";

// Register one icon (raw SVG string)
registerIcon("my-icon", `<svg viewBox="0 0 24 24">...</svg>`);

// Register many at once
registerIcons([
  { name: "icon-a", svg: `<svg>...</svg>` },
  { name: "icon-b", svg: `<svg>...</svg>` },
]);

// Retrieve
const svg = getIcon("my-icon");
```

`getIcon` returns the raw registered string. `<y-icon>` and `<y-rating>` render through the shared SVG sanitizer (see _SVG Sanitizer_ below), so script tags, event-handler attributes (`onload`, `onclick`, …), and any element outside the allowlist are stripped before the markup reaches the DOM — registering hostile SVG cannot lead to script execution through these components.

## Helper Functions (internal, `src/modules/helpers.js`)

These are not exported in the public API but are used internally:

- `createElement(tag, attrs, children)` — single-call DOM builder used by every component to assemble its shadow tree without `innerHTML` (attributes flow through `setAttribute`, so user-controlled values cannot break out into new attributes or markup)
- `getColorVarPair(color, fallbackColor)` — resolves a color name to `[bg, fg]` CSS value pair. Predefined names return token `var()` pairs; hex/rgb/hsl values return the raw color with a WCAG-contrasted foreground via `contrastTextColor()`
- `isSafeCssColor(value)` — strict allowlist that returns `true` for `#hex`, `rgb()`/`rgba()`, and `hsl()`/`hsla()` literals only. Components that paint a user-supplied color into a CSS context (`y-badge`'s `color`, `y-select`'s per-option `color`) gate the value through this helper and fall back to the semantic default when it fails
- `hideEmptySlotContainers(shadowRoot, config)` — hides wrappers when slots are empty
- `resolveCSSColor(varExpr, element)` — resolves CSS variable to computed color
- `manageLabelVisibility(labelWrapper)` — toggles label wrapper visibility on slotchange
- `parseColor(colorStr)` — parses hex/rgb to `{r, g, b}`
- `luminance({r,g,b})` — WCAG relative luminance
- `contrastTextColor(bgColor)` — returns `"#000"` or `"#fff"` for best contrast
- `clamp(v, min, max)` — clamp a number to a range
- `hsvToRgb(h, s, v)` — HSV → RGB (0-255)
- `rgbToHsv(r, g, b)` — RGB → HSV
- `hsvToHsl(h, s, v)` — HSV → HSL
- `hslToHsv(h, s, l)` — HSL → HSV
- `rgbToHex(r, g, b)` — RGB → hex string
- `rgbaToHex(r, g, b, a)` — RGBA → hex8 string
- `parseHexColor(hex)` — hex → `{r, g, b, a}`
- `parseColorString(str)` — any supported CSS color string → `{r, g, b, a}`

### SVG Sanitizer (internal, `src/modules/svg-sanitizer.js`)

Shared by `<y-icon>` and `<y-rating>` so both consume one allowlist-based sanitizer. Built-in icons are bundled and trusted; the sanitizer's job is to defend against script-bearing SVG passed through `registerIcon(name, svg)` at runtime.

- `sanitizeSvg(raw)` — parses an SVG string, strips every element and attribute outside the allowlist, and returns the resulting `outerHTML`. Empty input or markup with no `<svg>` root returns `""`
- `getSanitizedIcon(name)` — looks up a registered icon, sanitizes it, and memoizes the result. Repeated calls with the same name reuse the cached sanitized string
