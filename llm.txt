# YumeKit (@waggylabs/yumekit)

A modern, framework-agnostic Web Components UI kit providing 60 production-ready custom HTML elements. Built entirely on native web standards with zero external runtime dependencies.

## Version
0.5.5-beta.1

## License
MIT

## Installation

```bash
npm install @waggylabs/yumekit
```

## Key Characteristics
- Pure Web Components (Custom Elements v1, Shadow DOM, ElementInternals)
- Zero runtime dependencies
- Full TypeScript support with type declarations
- Tree-shakeable ESM modules
- ARIA-compliant and keyboard-navigable
- Design token system via CSS custom properties
- 60 built-in themes: 14 color families (blue, slate, mono, orange, green, red, teal, yellow, indigo, purple, pink, rose, brown, olive — `slate` is a desaturated bluish-gray (grey-dominant) cool neutral, `mono` is a shadcn-style monochrome family with a near-black/near-white primary on the default neutral surfaces, and `rose` is a muted dusty-rose) × dark and light variants; design-system families that also override shape and typography, not just color: Material Design 3 (`material-blue-*` and `material-purple-*`, rounded + Roboto), IBM Carbon (`carbon-light` / `carbon-dark`, sharp 0px corners + IBM Plex Sans), Ant Design (`ant-blue-*` daybreak blue `#1677ff` and `ant-green-*` polar green, 6px corners + native system-font stack), Tailwind/shadcn on Slate neutrals + Inter + 8px corners (monochrome `shadcn-light` / `shadcn-dark` plus Tailwind-blue `shadcn-blue-light` / `shadcn-blue-dark`, `#2563eb` primary), GitHub Primer (`primer-light` / `primer-dark` / `primer-dark-dimmed`), and Bootstrap (`bootstrap-light` / `bootstrap-dark`); plus two curated palette sets: Catppuccin (`catppuccin-latte` / `-frappe` / `-macchiato` / `-mocha`) and Nord (`nord` / `nord-aurora`); and `waggy` / `waggy-dark`, a high-contrast wild-palette theme (light + dark) with heavily rounded corners, thick borders (black on light, white on dark), hard offset shadows, and bottom-weighted per-side borders on buttons/fields/surfaces; and Kepler (`kepler-light` / `kepler-dark` / `kepler-amber` / `kepler-galaxy` / `kepler-matrix`), a retro terminal family in the Tomorrow typeface with fully squared 0px corners — neutral light/dark plus three tinted dark flavors (Amber orange-on-black, Galaxy blue-tinted, Matrix green-on-black) (60 themes total)
- React JSX type declarations included
- Form-associated components with native HTML form API support
- Security-focused SVG icon sanitization (allowlist-based)

## Entry Points (package.json exports)

- `@waggylabs/yumekit` — full ESM bundle
- `@waggylabs/yumekit/react` — React JSX type declarations
- `@waggylabs/yumekit/components/y-{name}` — individual components
- `@waggylabs/yumekit/icons/all.js` — all pre-built icons (line + filled variants)

CDN (IIFE):

```html
<script src="https://cdn.jsdelivr.net/npm/@waggylabs/yumekit/dist/yumekit.min.js"></script>
```

```javascript
import "@waggylabs/yumekit";
```

### Tree-Shaken Import
```javascript
import "@waggylabs/yumekit/components/y-theme";
import "@waggylabs/yumekit/components/y-button";
import "@waggylabs/yumekit/components/y-input";
```

```javascript
import { registerIcon, registerIcons, getIcon, getIconNames } from "@waggylabs/yumekit";
import "@waggylabs/yumekit/icons/all.js"; // load all 100+ pre-built icons
```

### React
```jsx
import "@waggylabs/yumekit";
// JSX types are auto-resolved via react.d.ts

function App() {
  return (
    <y-theme theme="blue-light">
      <y-button color="primary">Click me</y-button>

  );

```

### y-theme
Theme provider. Wraps your app and injects design tokens as CSS custom properties.

Attributes:
- `theme` — built-in palette name or a URL/path to a custom CSS theme file. Built-in names: `"blue-light"` | `"blue-dark"` | `"slate-light"` | `"slate-dark"` | `"mono-light"` | `"mono-dark"` | `"orange-light"` | `"orange-dark"` | `"green-light"` | `"green-dark"` | `"red-light"` | `"red-dark"` | `"teal-light"` | `"teal-dark"` | `"yellow-light"` | `"yellow-dark"` | `"indigo-light"` | `"indigo-dark"` | `"purple-light"` | `"purple-dark"` | `"pink-light"` | `"pink-dark"` | `"brown-light"` | `"brown-dark"` | `"olive-light"` | `"olive-dark"` | `"material-blue-light"` | `"material-blue-dark"` | `"carbon-light"` | `"carbon-dark"` | `"ant-blue-light"` | `"ant-blue-dark"` | `"shadcn-light"` | `"shadcn-dark"` | `"shadcn-blue-light"` | `"shadcn-blue-dark"` | `"waggy"` | `"kepler-light"` | `"kepler-dark"` | `"kepler-amber"` | `"kepler-galaxy"` | `"kepler-matrix"` (plus `primer-*`, `bootstrap-*`, `catppuccin-*`, `nord` / `nord-aurora`, `rose-*`, `mono-*`, `material-purple-*`, `ant-green-*` — see the full list above)
- `cross-origin` — boolean, enables CORS for remote theme URLs

### y-break
Decorative divider that draws a horizontal or vertical line, optionally broken by centered content.

Tag: `<y-break>`
Attributes:
- `orientation` — `"horizontal"` (default) | `"vertical"`. Vertical breaks need a height from their container (flex/grid parent or explicit height).
- `align` — `"start"` | `"center"` (default) | `"end"` — position of the centered content along the line.
- `variant` — `"solid"` (default) | `"dashed"` | `"dotted"` — line style.
- `label` — string, plain text rendered in the center.
- `icon` — registered icon name rendered in the center (icon then label when both are set).
- `inset` — `"none"` (default) | `"small"` | `"medium"` | `"large"` — padding applied to the outer ends of the line(s).

Slots: default — slotted content takes precedence over `label` / `icon`.
CSS Parts: `line`, `line-start`, `line-end`, `content`.

The host receives `role="separator"`, plus `aria-orientation="vertical"` when vertical (horizontal is the implicit default and is omitted). With no slotted content, label, or icon, a single unbroken line is rendered.

`--component-break-line-style` overrides the `variant` attribute per instance without re-render. The line color defaults to the semantic border token (`--base-border`) via `--component-break-line-color`. The host applies default perpendicular spacing around the line (block axis when horizontal, inline when vertical) via `--component-break-spacing` (defaults to `--spacing-medium`) so the break separates content without extra wrapper margins; set it to `0` to opt out. `--inset` (the `inset` attribute) still controls padding at the outer *ends* of the line — distinct from `--component-break-spacing`, which is the gap perpendicular to it.

```html
<y-break></y-break>
<y-break label="OR"></y-break>
<y-break icon="star" variant="dashed"></y-break>
<y-break align="start" inset="medium"><y-tag color="primary">New section</y-tag></y-break>
```

### y-button
Pressable button with icon support.

Tag: `<y-button>`
Attributes:
- `color` — predefined scheme (`"base"` | `"primary"` | `"secondary"` | `"success"` | `"warning"` | `"error"` | `"help"`) or any CSS color (`#hex`, `rgb()`, `hsl()`)
- `size` — `"small"` | `"medium"` (default) | `"large"`
- `variant` — `"outlined"` (default) | `"filled"` | `"flat"`
- `style-type` — **deprecated** alias for `variant`; still honored (with `variant` winning if both are set) but will be removed in a future major version
- `padding-mode` — `"auto"` (default) | `"square"` | `"wide"`. Controls whether the inline padding collapses to the block value: `auto` does so for icon-only buttons; `square` forces it (e.g. paginator number buttons); `wide` never does
- `left-icon` — icon name (from registry)
- `right-icon` — icon name (from registry)
- `disabled` — boolean
- `type` — `"button"` | `"submit"` | `"reset"` (default: `"button"`)
- `href` — when set, the button renders as an anchor (`<a>`) pointing at this URL
- `target` — anchor target (e.g. `"_blank"`); only applies when `href` is set
- `rel` — anchor `rel` (e.g. `"noopener noreferrer"`); only applies when `href` is set
- Native form-submission attributes (`form`, `formaction`, `formmethod`, `formenctype`, `formnovalidate`, `formtarget`, `autofocus`) and ARIA attributes (`aria-label`, `aria-pressed`, `aria-expanded`, `aria-haspopup`, `aria-controls`) are reflected onto the underlying control.

```html
<y-button color="primary" size="large" left-icon="check">Save</y-button>

<!-- Link button -->
<y-button href="/docs" target="_blank" rel="noopener">Docs</y-button>
```

CSS Custom Properties (per `small|medium|large`): `--component-button-padding-{size}` sets padding on all sides; `--component-button-padding-block-{size}` and `--component-button-padding-inline-{size}` override the vertical / horizontal axes independently and fall back to `--component-button-padding-{size}` when unset (the Material and Shadcn themes use this for wider buttons). Whether the inline axis collapses to the block value is governed by the `padding-mode` attribute above (default `auto` = collapse for icon-only buttons). `--component-control-height-{size}` sets the min-height (shared with `y-input` so fields and buttons stay the same height per theme); falls back to `--sizing-{size}`. For `variant="outlined"`, the border is sourced from the button's matching semantic border token (`--base-border`, `--primary-border`, `--error-border`, …) per `color`, falling back to the button's text color when that token is unset. `--component-button-border-width` sets the border width and is applied as the `border-width` longhand (not baked into a shorthand), so it accepts a 1–4 value pattern for per-side widths (e.g. `1px 2px` or `0 0 2px 0` for a bottom-only border); defaults to `1px`. Two optional global overrides remain: `--component-button-outline-border` overrides the border style + color as a CSS `border` shorthand (e.g. `1px solid var(--base-border)`) — note its width is superseded by `--component-button-border-width` — and `--component-button-outline-border-color` sets just the border color across resting/hover/focus/active — set either via CSS or a scoped `y-theme` to flatten all outlined borders to one color.

### y-input
Text input field. Form-associated.

Tag: `<y-input>`
Attributes:
- `type` — `"text"` | `"email"` | `"password"` | `"number"` | `"tel"` | `"url"` | `"search"`
- `name` — form field name
- `value` — current value
- `placeholder`
- `label` — visible label text
- `label-position` — `"top"` (default) | `"bottom"` | `"left"` | `"right"`
- `size` — `"small"` | `"medium"` | `"large"`
- `variant` — `"default"` (full border) | `"underline"` (bottom border only, square bottom corners — Material/Carbon field style)
- `disabled` — boolean
- `readonly` — boolean
- `required` — boolean
- `invalid` — boolean, applies error state
- `max-length` — numeric string
- `min-length` — numeric string
- `min`, `max`, `step` — numeric constraints applied when `type="number"`
- `pattern` — validation regex
- `autocomplete` — forwarded to the inner `<input>` (e.g. `"email"`, `"current-password"`)
- `error-text` — validation message rendered below the field; also applies the error state and becomes the input's accessible description

Accessibility: `aria-label` / `aria-labelledby` set on the host are forwarded to the inner control, so the accessible name actually reaches what a screen reader reads (setting them on the host alone does not). `error-text` renders its message inside this component's own shadow root and wires `aria-describedby` + `aria-invalid` there — an `aria-describedby` pointing at an element outside the component cannot resolve across the shadow boundary, so pass the message in rather than an id.

Events: `input` (detail: `{ value }`) on every keystroke, `change` (detail: `{ value }`) on commit — native semantics, so blur after an edit, or Enter. Setting `value` programmatically fires neither. Both bubble and are composed; the inner control's own native `change` is not composed and never escapes the shadow root, so listen on the host.

CSS Custom Properties: `--component-input-background`, `--component-input-background-disabled`, `--component-input-color`, `--component-input-border-color`, `--component-input-accent`, `--component-input-label-color`, `--component-input-placeholder-color` (also used by `y-textarea`, `y-date`, and `y-color` for their placeholder text), `--component-input-icon-color`, `--component-input-error-color`, `--component-input-error-background`, `--component-input-error-border-color`. Shared across all form fields: `--component-inputs-border-width` (applied as the `border-width` longhand — accepts a 1–4 value pattern for per-side widths, e.g. `0 0 1px 0`) and `--component-inputs-border-radius-outer` (also takes a 1–4 value pattern). For a true underlined field prefer `variant="underline"`, which also squares the bottom corners.

```html
<y-input type="email" name="email" label="Email" required></y-input>
```

### y-date
Date input field with popup calendar. Form-associated.

Tag: `<y-date>`
Attributes:
- `mode` — `"single"` (default) | `"range"`
- `name` — form field name
- `value` — ISO date string, or `"ISO,ISO"` comma-pair for range mode
- `min`, `max` — date constraints (ISO string)
- `format` — display format string. Tokens: `YYYY` `MM` `DD` `HH` `hh` `mm` `ss` `A` `a` (default: `"MM/DD/YYYY"`)
- `placeholder` — placeholder text when no date is selected
- `color` — color scheme for the datepicker (default: `"primary"`)
- `size` — `"small"` | `"medium"` (default) | `"large"`
- `label-position` — `"top"` (default) | `"bottom"`
- `variant` — `"default"` (full border) | `"underline"` (bottom border only, square bottom corners)
- `clearable` — boolean, shows a clear (×) button when a value is set
- `disabled` — boolean
- `invalid` — boolean, applies error state
- `show-hours` — boolean, show hour column in time picker
- `show-minutes` — boolean, show minutes column (implies `show-hours`)
- `show-seconds` — boolean, show seconds column (implies `show-minutes`)
- `hour-format` — `"12"` (default) | `"24"`, 12- or 24-hour clock in time picker
- `minute-interval` — step between minute options (default: `5`)
- `second-interval` — step between second options (default: `5`)
- `show-years` — `"true"` (default) | `"false"`, toggles year select in calendar header
- `show-months` — `"true"` (default) | `"false"`, toggles month select in calendar header
- `show-days` — `"true"` (default) | `"false"`, toggles the day grid (use `"false"` for month or year picker)
- `mobile-breakpoint` — viewport width in px below which mobile mode activates (default: `768` or `--component-datepicker-mobile-breakpoint`)
- `native-mobile` — boolean, when set renders native `<input type="date">` elements on mobile instead of the popup datepicker

Events: `change` (detail: `{ value, startDate, endDate, formatted }`)
Methods: `open()`, `close()`, `clear()`
Slots: `label`, `left-icon`

```html
<y-date name="appt" format="MM/DD/YYYY" clearable>
  <span slot="label">Appointment Date</span>
</y-date>

<!-- Date range -->
<y-date name="trip" mode="range">
  <span slot="label">Travel Dates</span>
</y-date>

<!-- Date + time -->
<y-date name="meeting" show-hours format="MM/DD/YYYY hh:mm A">
  <span slot="label">Meeting Time</span>
</y-date>

<!-- Use native inputs on mobile (opt-in) -->
<y-date name="dob" native-mobile clearable>
  <span slot="label">Date of Birth</span>
</y-date>
```

### y-editor
Rich text (WYSIWYG) editor built on contenteditable. Form-associated; its value is sanitized HTML. Use y-textarea for plain multi-line text and y-code for read-only code display.

Tag: `<y-editor>`
Attributes:
- `name` — form field name
- `value` — content as sanitized HTML; reflected on `change`, not on every keystroke
- `mode` — `"rich"` (default and only supported value in v1; reserved for a future markdown mode)
- `toolbar` — space-separated tool ids, `|` for a group separator. Default: `"bold italic underline strike | heading blockquote code | ordered-list unordered-list | link image | undo redo"`. `"false"` hides the toolbar. Tool ids: `bold`, `italic`, `underline`, `strike`, `inline-code`, `heading`, `blockquote`, `code`, `ordered-list`, `unordered-list`, `link`, `image`, `undo`, `redo`
- `placeholder`
- `rows` — visible rows at the default font size (default: `"6"`)
- `max-length` — max character count of the plain-text content; blocks further input and marks invalid
- `show-count` — boolean; renders a character counter (`n / max-length` when `max-length` is set)
- `size` — `"small"` | `"medium"` | `"large"`
- `disabled` — boolean; non-editable, non-focusable, excluded from submission
- `readonly` — boolean; non-editable but focusable; toolbar hidden; still submits
- `required` — boolean; invalid when the plain-text content is empty
- `invalid` — boolean, applies error state
- `allowed-blocks` — space-separated block types (default: `"p h1 h2 h3 blockquote ul ol code"`). Anything outside the list normalizes to `p`. Block tools not permitted here are dropped from the toolbar automatically
- `image-upload` — boolean; routes image insertion through the `image-upload` event instead of inlining the source
- `triggers` — mention triggers; JSON array of `{trigger, type?, minChars?, maxChars?, allowSpaces?, insert?, atomic?}`. Empty (the default) disables mentions entirely
- `mention-loading` — boolean; shows the mention popup's busy state
- `mention-query-delay` — debounce in ms before `mention-query` fires (default: `"150"`)

Properties (not attributes): `selection` (readonly) — `{blockType, bold, italic, underline, strike, code, link}` at the caret; `textContent` (readonly) — plain text of the document; `mentionCandidates` — the candidate list for the open popup; `triggers` — the trigger array (rich data, not reflected).

Slots: default (initial content — parsed, sanitized, adopted as the starting value when no `value` attribute), `label`, `toolbar-start`, `toolbar-end`, `footer` (replaces the character counter), `mention-empty` (no matches; default "No matches"), `mention-loading` (busy state).

Events: `input` `{value}`, `change` `{value}` (on blur when changed), `selection-change` `{selection}`, `image-upload` `{file, insert(url), reject(reason)}`, `link-click` `{href, text}` (cancelable — canceling suppresses the link popover), plus the mention events below.

Shortcuts: Ctrl/Cmd+B bold, +I italic, +U underline, +K link, +Shift+X strike, +E inline code, +Alt+1..3 headings, +Shift+7/8 ordered/unordered list, +Shift+. blockquote, +Z / +Shift+Z undo/redo, +Shift+V paste as plain text.

Mention triggers: caret-triggered autocomplete for `@name` mentions, `#topic` tags, or any literal prefix. The component never fetches — it detects the trigger, debounces, emits `mention-query` `{trigger, type, query, id}`, and renders whatever the app supplies via `setMentionCandidates(id, candidates)`. A candidate is `{value, label?, description?, icon?, avatar?, disabled?}`; `avatar` (an image URL) wins over `icon` (a `y-icon` name).

- A trigger only activates at a word boundary — start of the text, start of a block, or right after whitespace or an opening bracket — so `a@b` in an email address does not open the popup. The fragment ends at whitespace unless `allowSpaces` lets it span a single space, and exceeding `maxChars` (default 32) abandons it.
- Insertion replaces the fragment (trigger character included) with the `insert` template — `"{trigger}{label} "` by default, with `{trigger}`, `{value}`, and `{label}` substituted. The result always ends in whitespace, so the mention reads as a finished word: a single space is appended only when the template does not already end in whitespace, and whitespace the template specifies is kept as written. Insertion is a single undo step, and never reopens the popup on the text it just wrote — even when that text would match the trigger again (`@ada ` under an `allowSpaces` trigger). The trigger goes live again as soon as the query text moves on.
- With `atomic: true` (y-editor only) the mention becomes one `contenteditable="false"` inline element carrying `data-mention-type` / `data-mention-value`. It deletes with one Backspace, survives the sanitize/serialize round trip in `value`, and counts toward `max-length` as its rendered template.
- The popup is anchored to the caret rather than to the trigger character, so it stays beside what is being typed however long the query grows and follows the text down when the line wraps. It flips above the caret when it would overflow the viewport.
- Methods: `setMentionCandidates(id, candidates)` (a superseded or closed query id is ignored, so a slow app response cannot repopulate a moved-on popup), `closeMentions()`, `insertMention(candidate, trigger?)`.
- Events: `mention-query` `{trigger, type, query, id}`, `mention-insert` `{trigger, type, candidate, text, range}` (cancelable — canceling suppresses the default insertion), `mention-close` `{trigger, type, reason}` where reason is `"escape" | "blur" | "no-match" | "insert" | "caret-moved"`.
- Accessibility: while the popup is open the editing surface takes `role="combobox"` + `aria-expanded` / `aria-controls` / `aria-autocomplete="list"` / `aria-haspopup="listbox"`, and `aria-activedescendant` tracks the highlight — focus and the caret never leave the text. Down/Up move the highlight, Enter/Tab insert, Escape closes and keeps the typed text. All of it reverts on close. Nothing triggers while `disabled` or `readonly`, and detection is suspended during IME composition.

```html
<y-editor triggers='[{"trigger":"@","type":"user"}]' placeholder="Type @ to mention someone">
  <span slot="mention-empty">Nobody by that name</span>
</y-editor>
<script>
  editor.addEventListener("mention-query", (e) => {
    const { query, id } = e.detail;
    editor.setMentionCandidates(id, people.filter((p) => p.label.includes(query)));
  });
</script>
```

Security: every path that introduces HTML (`value`, the default slot, paste) runs through `src/modules/html-sanitizer.js`. Only the tags implied by `allowed-blocks` plus inline formatting, `<a>` and `<img>` survive; `on*`, `<script>`, `<style>`, `<iframe>` are stripped; only `http`, `https`, `mailto` and `data:` raster images are permitted on `href`/`src`.

```html
<y-editor name="body" placeholder="Write something..." rows="8" show-count max-length="500">
  <span slot="label">Description</span>
</y-editor>
```

### y-select
Dropdown/multi-select. Form-associated.

Tag: `<y-select>`
Attributes:
- `options` — JSON string: `[{"value": "1", "label": "Option 1"}, ...]`. Each option also takes an optional `color` — a semantic name (`primary`, `success`, …) or a CSS color literal gated by `isSafeCssColor`
- `value` — selected value string (comma-separated for multiple)
- `name` — form field name
- `placeholder`
- `size` — `"small"` | `"medium"` | `"large"`
- `variant` — `"default"` (full border) | `"underline"` (bottom border only, square bottom corners; trigger only — the dropdown panel keeps its border)
- `disabled` — boolean
- `required` — boolean
- `invalid` — boolean, applies error state
- `multiple` — boolean; allows multiple selections
- `display-mode` — `"tag"` renders selected items as removable tags (requires `multiple`)
- `searchable` — boolean; replaces the value display with an inline text input that filters the dropdown options as the user types (autocomplete style). In single mode the selected label is shown in the input when closed and cleared when opened. In multi-tag mode the input appears after the last tag.
- `clearable` — boolean; shows a clear (×) button when a value is selected. Works independently of `searchable`.
- `label-position` — `"top"` (default) | `"bottom"`
- `close-on-click-outside` — set to `"false"` to keep the dropdown open when clicking outside
- `portal` — boolean; renders the dropdown into the nearest `<y-theme>` (falling back to `<body>`) so it escapes scrollable, clipped, or low-stacking ancestors (e.g. inside a data-grid cell editor or dialog)
- `error-text` — validation message rendered below the field; also applies the error state and becomes the combobox's accessible description

A selected option with a `color` is filled solidly with it. Hovering an unselected one instead tints the row — the color as the text over a light wash of it — so the assignment reads before the option is committed, without looking selected. Options without a `color` keep the neutral hover.

The trigger carries `role="combobox"` with `aria-expanded` / `aria-haspopup`, the panel `role="listbox"`, and each option `role="option"` with `aria-selected`.
Accessibility: `aria-label` / `aria-labelledby` set on the host are forwarded to the inner control, so the accessible name actually reaches what a screen reader reads (setting them on the host alone does not). `error-text` renders its message inside this component's own shadow root and wires `aria-describedby` + `aria-invalid` there — an `aria-describedby` pointing at an element outside the component cannot resolve across the shadow boundary, so pass the message in rather than an id.

Events: `change`

### y-tokens
Multi-value token (chip) input with typeahead. Form-associated. The user types into a single-line field and commits entries as removable tokens, optionally chosen from a suggestion list. Fills the gap between `y-select multiple` (a dropdown over a fixed option list) and `y-tag` (display only): use it for facet chips (`allow-custom` off) and free-form topic/recipient entry (`allow-custom` on).

Tag: `<y-tokens>`
Attributes:
- `value` — the committed tokens. Property: an array of `Token` objects or bare strings. Attribute: a JSON array or a separator-delimited string (`value="a, b, c"`). Rich data, **not reflected** — reading the property always returns objects
- `options` — suggestion list, same shape as a token. JSON array attribute or an array property. Rich data, not reflected. In async mode the app replaces this in response to `query`
- `name` — form field name; **one entry per token** is submitted under it, so three tokens produce three `name=…` pairs rather than one joined string
- `async` — boolean; typing emits `query` instead of filtering `options` locally. The component **never** fetches
- `loading` — boolean; shows the busy state in the popup. Set automatically between `query` and the next `options` assignment; the app may also set it
- `query-delay` — number of ms to debounce before `query` is emitted (default `200`; `0` disables debouncing)
- `filter` — `"contains"` (default) | `"starts-with"` | `"none"`. Local matching of `options` against the typed text; `"none"` means the app has already filtered
- `allow-custom` — boolean; whether text matching no option may become a token. Off for facets, on for free entry
- `max` — number; maximum token count. At the limit commits are blocked and the control reports `rangeOverflow`
- `duplicates` — `"ignore"` (default; the repeat is dropped, the existing token pulses, the live region announces it) | `"allow"` | `"error"` (dropped, and the control goes invalid). Comparison is on `value`, case-insensitive, with the first-committed casing kept for display. This governs values arriving as **text** (typed, pasted, separator-committed); the listbox is `aria-multiselectable`, so activating an already-committed option there toggles it back off instead — as `y-select multiple` does — except under `"allow"`, where no single token a toggle could mean exists and another copy is added
- `separators` — characters that commit the pending text in addition to Enter (default `","`; each character is its own separator, e.g. `separators=",;"`)
- `placeholder` — hint shown while the field is empty; hidden once a token exists
- `placeholder-persist` — boolean; keep the placeholder visible while tokens are present
- `token-variant` — `"filled"` (default) | `"outlined"` | `"flat"`, forwarded to each token's `y-tag`. Tokens with no `color` use `primary`, so a token strip reads the same as `y-select multiple display-mode="tag"`
- `token-shape` — `"square"` (default) | `"round"`, forwarded to each `y-tag`
- `size` — `"small"` | `"medium"` (default) | `"large"`. Tokens render one step down
- `variant` — `"default"` (full border) | `"underline"` (bottom border only, square bottom corners)
- `label-position` — `"top"` (default) | `"left"` | `"hidden"`
- `clearable` — boolean; shows a control that removes every token at once
- `portal` — boolean; renders the popup into the nearest `<y-theme>` (falling back to `<body>`) so it escapes clipped or low-stacking ancestors. Custom properties set **inline on the host** are forwarded onto the portal, so a per-instance override still reaches the popup once it has been moved out — set `--component-select-z-index` inline to lift it above another portaled surface such as a dialog
- `disabled` — boolean; non-interactive and excluded from form submission
- `readonly` — boolean; tokens are visible and focusable but not removable, and there is no input or popup
- `required` — boolean; at least one token (`valueMissing`)
- `invalid` — boolean, forces the error state
- `error-text` — validation message rendered below the control; also applies the error state and becomes the combobox's accessible description

Token / Option shape: `{value, label?, icon?, color?, invalid?, disabled?}` — `value` is required and is the identity used for dedupe and form submission; `label` falls back to `value`; `icon` is a `y-icon` name rendered leading inside the chip; `color` is a semantic name or a CSS color gated by `isSafeCssColor`; `invalid` renders the token in the error state (it stays visible and removable — a token the user typed is never silently dropped); `disabled` applies to options only.

Slots: `label`, `left-icon` (before the token strip), `empty` (fallback "No matches"), `loading` (fallback: a spinner and "Searching…").

Events:
- `change` — `{value}` when tokens are added, removed, or cleared; `value` is the new array
- `token-add` — **cancelable**; `{token, source}` before a token is appended, where `source` is `"enter"|"separator"|"paste"|"select"|"api"`. Preventing it blocks the add and leaves the text in the input
- `token-remove` — **cancelable**; `{token, index, source}` before a removal, where `source` is `"click"` (the chip's own control) | `"deselect"` (an already-committed option toggled off in the popup) | `"backspace"` | `"clear"` | `"api"`
- `query` — async mode only; `{query, id}`. The app filters and assigns `options`; `id` correlates the response
- `input` — `{text}` when the pending text changes. Does not fire on commit

Methods: `addToken(token)`, `removeToken(index, source?)`, `clear()`, `openPopup()`, `closePopup()`, `focus()`, `checkValidity()`, `reportValidity()`, and `setOptions(options, queryId?)` — passing the `id` from a `query` event makes the assignment a no-op once a newer query has gone out, so stale async responses are discarded. Read-only `validity` / `validationMessage`.

Keyboard: one tab stop for the whole control. `Down`/`Up` move the suggestion highlight (opening the popup, wrapping, skipping disabled options); `Enter` commits the highlighted option, or the typed text when nothing is highlighted and `allow-custom` is set — it is swallowed only when the popup is open or text is pending, so an empty field still submits the form; any `separators` character commits; `Escape` closes the popup without clearing the text, and a second `Escape` clears it; `Left`/`Right` from an empty input move the highlight through the token strip and back; `Backspace` in an empty input highlights the last token and only a **second, separate** press deletes it (auto-repeat is ignored, so a held key cannot eat the field); `Backspace`/`Delete` on a highlighted token removes it; `Home`/`End` jump to the first/last token. Blur commits the pending text when `allow-custom` is set, and otherwise discards and announces it.

Accessibility: ARIA 1.2 combobox — `role="combobox"` on the input with `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, and `aria-activedescendant` tracking the highlighted option or token so DOM focus never leaves the input. The popup is `role="listbox"` with `role="option"` children; the token strip is a `role="list"` of `role="listitem"` chips. Each remove control names its own token (`aria-label="Remove Design"`), never a generic "Remove tag". A polite live region reports the suggestion count on each filter and every add and remove. `aria-label` / `aria-labelledby` on the host are forwarded to the input.

Validation: `valueMissing` when `required` and empty, `rangeOverflow` past `max`, `customError` when a token carries `invalid: true` or `duplicates="error"` is triggered. `formResetCallback` restores the initial `value`; `formStateRestoreCallback` restores from session state.

A committed option stays in the list rather than disappearing, rendered with the `y-select` accent fill (or its own `color`, gated by `isSafeCssColor`) and `aria-selected="true"`; the keyboard highlight shows as an inset ring on those rows so it stays visible over the fill. An uncommitted option carrying a `color` hovers and highlights in that color — colored text over a light wash of it — as `y-select` does.

CSS Parts: `wrapper label control token-list token token-remove input clear-button popup option option-icon option-label empty loading error-text`
CSS Custom Properties: `--component-tokens-gap`, `--component-tokens-padding-{small|medium|large}`, `--component-tokens-min-height-{small|medium|large}`, `--component-tokens-max-height`, `--component-tokens-input-min-width`, `--component-tokens-popup-max-height`. Chip appearance reuses the existing `--component-tag-*` tokens and field chrome reuses `--component-input-*` / `--component-inputs-*` — no parallel token set is introduced for the chips.

```html
<!-- Facet chips: only the listed options may be committed -->
<y-tokens name="team" clearable placeholder="Filter by team…"
    options='[{"value":"design","label":"Design","color":"primary"},{"value":"eng","label":"Engineering","color":"success"}]'
    value='["design"]'>
    <span slot="label">Team</span>
</y-tokens>

<!-- Free entry: anything the user types becomes a token -->
<y-tokens name="topics" allow-custom separators=",;" max="5" placeholder="Add a topic…"></y-tokens>
```

```js
// Async suggestions — the component asks, the app answers.
const tokens = document.querySelector("y-tokens");
tokens.async = true;
tokens.addEventListener("query", async ({ detail: { query, id } }) => {
    const results = await fetch(`/api/topics?q=${encodeURIComponent(query)}`).then((r) => r.json());
    tokens.setOptions(results, id); // ignored if a newer query already went out
});
```

### y-code
Lightweight, dependency-free code block. Renders slotted source text with optional line numbers, a copy-to-clipboard button, a `max-lines` collapse, and an optional filename header. Built-in tokenizer covers **JavaScript** (aliases: `js` / `jsx` / `mjs` / `cjs`), **TypeScript** (aliases: `ts` / `tsx` / `mts` / `cts`), **JSON**, **CSS**, **Python** (aliases: `py` / `python3`), **Bash** (aliases: `sh` / `shell` / `zsh`), and **HTML** (aliases: `htm` / `xml` / `svg`); other languages fall back to plain text. The HTML tokenizer does not recurse into `<style>` / `<script>` bodies (they render as text). Consumers can also pipe the output of an external highlighter (Prism, shiki, etc.) through the sanitized `highlighted` slot — that path wins when both are available. Span markup is sanitized to an allowlist of `<span>` + token class names; emitted classes are Prism-compatible (`token keyword`, `token string`, etc.) so existing Prism stylesheets layer on cleanly.

Tag: `<y-code>`
Attributes:
- `language` — string. Triggers built-in syntax highlighting for `javascript` (aliases: `js` / `jsx` / `mjs` / `cjs`), `typescript` (aliases: `ts` / `tsx` / `mts` / `cts`), `json`, `css`, `python` (aliases: `py` / `python3`), `bash` (aliases: `sh` / `shell` / `zsh`), and `html` (aliases: `htm` / `xml` / `svg`). Other values fall back to plain text. Also used in the `aria-label`. Case-insensitive. Default `"text"`.
- `line-numbers` — boolean. Renders line numbers on the left and makes each line a focusable / clickable target that copies the line text. On a successful line copy the row briefly flashes and a floating "Copied!" pill (using `copied-label`) appears anchored to that line.
- `max-lines` — number. When set, only this many lines render and the block shows a "Show N more lines" toggle.
- `wrap` — boolean. When set, long lines wrap; otherwise the block scrolls horizontally.
- `filename` — string. Renders a header bar containing the filename and the copy button. Empty hides the header.
- `copyable` — defaults to `true`. The copy button is shown by default; pass `copyable="false"` to hide it.
- `disabled` — boolean. Suppresses interactive controls (copy button, line click). Source code still renders.
- `copy-label` — string. Idle text on the copy button. Default `"Copy"`.
- `copied-label` — string. Text shown briefly after a successful copy. Default `"Copied!"`.

Slots:
- (default) — raw source code as plain text. Two authoring patterns:
    - **Plain text** — works for snippets where `<` and `&` are rare (JS, JSON, CSS, etc.). Consumer escapes any `<` / `&` so the browser doesn't interpret them as markup.
    - **`<template>` wrapper** — preferred for HTML / XML / SVG samples. The browser parses but does not render or execute `<template>` content, so the source is preserved verbatim with no escaping required. Example: `<y-code language="html"><template><div>hi</div></template></y-code>`. If any `<template>` child is present, it becomes the source and other text content in the default slot is ignored.

  Common leading whitespace is stripped from the source in both modes so indented authoring (`<y-code>\n    const x = 1;\n</y-code>`) renders flush-left. The block observes its light-DOM children and re-renders when they change, so frameworks (e.g. React) that reuse the element and swap its content across renders stay in sync without a manual refresh.
- `highlighted` — pre-highlighted markup (consumer-provided). Sanitized to allow only `<span>` with class names in the allowlist (Prism / common highlighter tokens: `keyword`, `string`, `comment`, `function`, `number`, `operator`, `punctuation`, `tag`, `attr-name`, `attr-value`, `selector`, `regex`, `boolean`, `constant`, `class-name`, `type`, `builtin`, `variable`, `property`, `namespace`, `token`, `deleted`, `inserted`, `important`, `italic`, `bold`). Other tags and other class names are stripped. Replaces the default-slot rendering when present.
- `header` — extra header content (e.g., a timestamp or status tag) rendered next to the filename.

Events (bubble + composed, non-cancelable):
- `copy` — `{ source, target: "block" | "line", lineIndex? }`. Fires on successful clipboard write.
- `copy-fail` — `{ error }`. Fires when clipboard access is denied or otherwise throws.
- `language-change` — `{ language }`. Fires when `setLanguage()` is called.

Methods: `copyBlock()` → Promise, `copyLine(index)` → Promise, `setLanguage(lang)`.

CSS Parts: `header`, `filename`, `copy-button`, `copy-feedback`, `pre`, `code`, `line`, `line-number`, `line-copied-badge`, `expand-toggle`.

Accessibility:
- `<pre>` has `role="region"` with `aria-label="<language> code, <N> lines"`.
- Copy button has `aria-label` and an `aria-live="polite"` label that updates to the `copied-label` on success.
- Each line, when `line-numbers` is set, has `role="button"`, `tabindex="0"`, and `aria-label="Copy line N of M"`; Enter/Space activate. A successful line copy surfaces a `role="status"` "Copied!" pill, so the result is announced to assistive tech as well as shown visually.

Security / trust model:
- **Default slot** is safe with any input. Text is read via `textContent` (or `template.innerHTML` for the `<template>` shortcut) and rendered into shadow DOM via `createTextNode` — the source string is never re-parsed as HTML.
- **`highlighted` slot** requires markup from a trusted source. The sanitizer protects what y-code renders into shadow DOM (allowlist of `<span>` + token class names), but the browser parses the slotted light-DOM children *before* this component upgrades, so any `<script>` tag inside the slot will execute regardless of our sanitizer. Pipe Prism / shiki output here, never arbitrary user input.
- The **`<template>` shortcut** is an authoring DX convenience, not a security boundary. It's safe in our pipeline because we read `template.innerHTML` as a string and feed it to the tokenizer; the string is never re-parsed as HTML. Don't rely on it to sanitize untrusted input.

CSS Custom Properties: `--component-code-bg-color`, `--component-code-text-color`, `--component-code-font-family`, `--component-code-font-size`, `--component-code-line-height`, `--component-code-border-radius`, `--component-code-border-width` (accepts a single length or a 4-value `top right bottom left` list), `--component-code-border-color`, `--component-code-header-bg-color`, `--component-code-copy-bg-color`, `--component-code-copy-hover-bg-color`, `--component-code-copy-text-color`, `--component-code-line-number-color`, `--component-code-line-number-width`, `--component-code-line-number-font-size`, `--component-code-line-hover-bg`, `--component-code-line-copied-bg`, `--component-code-line-copied-badge-bg`, `--component-code-line-copied-badge-text-color`, `--component-code-scrollbar-color`, `--component-code-scrollbar-bg`, plus per-syntax color hooks (`--component-code-keyword-color`, `--component-code-string-color`, `--component-code-comment-color`, `--component-code-function-color`, `--component-code-number-color`, `--component-code-operator-color`) used by the sanitized highlighted-slot markup.

```html
<y-code language="javascript" filename="hello.js" line-numbers>
function hello() {
    return "world";
}
</y-code>

<!-- HTML samples: wrap in <template> so the browser doesn't interpret them -->
<y-code language="html">
    <template>
        <div class="card">Hello, world!</div>
    </template>
</y-code>

<!-- Pre-highlighted via Prism / shiki -->
<y-code language="javascript">
    <div slot="highlighted"><span class="token keyword">const</span> x = <span class="token number">1</span>;</div>
</y-code>
```

### y-toggle
Segmented single-select control — a button group visually, a radio group semantically. Exactly one option is selected at a time and a thumb slides between segments as the value changes. Form-associated. Use it for mutually exclusive view or mode switches (list/grid, monthly/yearly, alignment) where every choice stays visible; use `<y-switch>` for binary on/off, `<y-tabs>` when the choice swaps a content panel, and `<y-button-group>` for a cluster of independent actions.

Tag: `<y-toggle>`
Attributes:
- `options` — array of `{ value, label?, icon?, color?, disabled?, ariaLabel? }`. `icon` is a `y-icon` name; `color` overrides the group's `color` while that option is selected, so the thumb recolors as it slides; supply `ariaLabel` for icon-only segments. Rich data: set the property for live data; the attribute accepts a JSON string as a seed and is not kept in sync after an imperative set.
- `value` — selected option value; reflected. Defaults to the first enabled option. A value naming an unknown or disabled option leaves nothing selected and hides the thumb.
- `name` — form field name
- `size` — `"small"` | `"medium"` (default) | `"large"`
- `variant` — `"solid"` (default, filled track) | `"outline"` (bordered track) | `"flat"` (no track). Each matches the `y-button` variant of the same name: `solid` and `flat` fill the selected segment with the color role and invert its text, `outline` tints it behind a border in the color role with matching text.
- `color` — the role marking the selected segment: `base`, `primary` (default), `secondary`, `success`, `warning`, `error`, `help`, or a CSS color literal. An unrecognised value falls back to `primary`. Set per-option via `options[].color` for status-style toggles where each choice carries its own meaning.
- `orientation` — `"horizontal"` (default) | `"vertical"`. The thumb slides along the matching axis.
- `full-width` — boolean; fills the container with equal-width segments
- `animate` — set to `"false"` to move the thumb instantly (default on). `prefers-reduced-motion: reduce` disables the slide either way.
- `disabled` — boolean; disables the whole group. Individual options disable via `options[].disabled`.

Methods: `select(value)` — the eventful path; fires `y-toggle-select` then `change`. Setting the `value` property or attribute moves the selection silently.

Slots: `option-{value}` — replaces a segment's label/icon with custom content.

Events: `y-toggle-select` (cancelable, detail `{ value, previousValue }`) before the change is applied; `change` (detail `{ value, previousValue }`) after. Both bubble and are composed.

Accessibility: the track is `role="radiogroup"` and each segment a `role="radio"` button. `aria-label` / `aria-labelledby` on the host are forwarded to the track. Roving tabindex — only the selected segment is tabbable; arrows move and select in one step (both axis pairs work in either orientation), `Home`/`End` jump to the ends, `Space`/`Enter` select the focused segment. Disabled segments are skipped.

Parts: `base` `track` `thumb` `segment` `label` `icon`

```html
<y-toggle
  name="view"
  aria-label="View mode"
  options='[{"value":"list","label":"List","icon":"list-bullet"},{"value":"grid","label":"Grid","icon":"grid"}]'
></y-toggle>

<y-toggle full-width color="primary" value="yearly"
  options='[{"value":"monthly","label":"Monthly"},{"value":"yearly","label":"Yearly"}]'></y-toggle>

<!-- Per-option color: each choice carries its own meaning -->
<y-toggle
  aria-label="Status"
  options='[{"value":"todo","label":"To do","color":"base"},{"value":"active","label":"Active","color":"warning"},{"value":"done","label":"Done","color":"success"}]'
></y-toggle>
```

### y-skeleton
Presentational placeholder that mimics the shape of content while it loads, reducing perceived latency and layout shift. Purely decorative — internals are `aria-hidden`. Compose multiple skeletons to approximate a final layout (e.g. a circle beside text lines for a user row).

Tag: `<y-skeleton>`
Attributes:
- `variant` — `"text"` (default) | `"circle"` | `"rect"`. `text` renders line bars with the component radius; `circle` renders a circle (avatars/icons); `rect` renders a rectangle with the component radius (images, cards, buttons).
- `width` — explicit width as any CSS length (e.g. `120px`, `60%`, `8rem`). Applied via a validated inline custom property. Default is variant-dependent (`text`/`circle`/`rect` default to `100%` unless sized by slotted content).
- `height` — explicit height as any CSS length. `text` defaults to `1em` per line; `circle` defaults to matching its width; `rect` needs an explicit height or slotted content.
- `lines` — `text` variant only; number of line bars (default `1`). When greater than 1, the last bar renders at ~60% width so it reads as a paragraph.
- `animation` — `"pulse"` (default) | `"wave"` | `"none"`. `pulse` fades opacity; `wave` sweeps a highlight gradient (clipped to the shape's radius); `none` is a static block. All animation is CSS keyframes only. Under `prefers-reduced-motion: reduce`, `pulse` and `wave` fall back to a static block.

Slots: default — optional sizing content, rendered invisible (`visibility: hidden`) so the skeleton inherits the exact dimensions of the element it stands in for. Explicit `width`/`height` take precedence over slotted content.

Accessibility: the component exposes no role or ARIA on itself; its internals are `aria-hidden="true"`. Set `aria-busy="true"` (and ideally `aria-live="polite"`) on the *container region* being loaded, and remove it when real content arrives.

CSS custom properties: `--component-skeleton-bg`, `--component-skeleton-highlight` (wave sweep), `--component-skeleton-radius`, `--component-skeleton-animation-duration`, `--component-skeleton-text-gap`.
CSS Parts: `skeleton` (each rendered shape; every line bar carries the part for multi-line `text`).

```html
<y-skeleton variant="text" lines="3"></y-skeleton>
<div aria-busy="true" style="display:flex;gap:16px;align-items:center">

  <div style="flex:1">
    <y-skeleton variant="text" width="60%"></y-skeleton>
    <y-skeleton variant="text" width="90%"></y-skeleton>

```

### y-form
Form container that lays out and manages a group of YumeKit form controls from a JSON `fields` array, renders submit/reset buttons, and collects all values into a single payload on submit.

Tag: `<y-form>`
Attributes:
- `fields` — JSON string (or array property): ordered field descriptors. Each entry renders a generated control (`type` + `name`), or — when it has a `slot` key — a named `<slot>` outlet at that position so a child with the matching `slot="…"` attribute interleaves with generated fields. Descriptor keys: `type` (`input` | `textarea` | `select` | `checkbox` | `radio` | `switch` | `slider` | `date` | `color` | `rating`; `input` also takes `inputType` for the native type), `name` (payload key, required for generated controls), `label`, `value` (initial), `placeholder`, `required`, `disabled`, `options` (for `select` / `radio`), `min` / `max` / `step`, `help` (helper text under the field), `autocomplete`, `errorText` (message shown in place of the generic "X is required" / "X is invalid" copy), `validate(value, values)` (returns a message string or `null`; runs after the built-in checks pass, for cross-field and domain rules), `slot` (named-outlet entry — other keys ignored). A `type` that is not one of the component types but names a native input type (`text`, `email`, `url`, `tel`, `number`, `password`, `search`, `time`, `datetime-local`, `month`, `week`) is sugar for `{type: "input", inputType: <that>}`. Rich data held as a property; the attribute seeds an initial value but is not kept in sync after an imperative set.
- `submit-text` — submit button label (default `"Submit"`)
- `reset-text` — reset button label (default `"Reset"`)
- `no-reset` — boolean; hide the reset button
- `layout` — `"vertical"` (default) | `"horizontal"` (fields wrap in a row) | `"inline"` (fields and actions on one line)
- `label-position` — `"top"` (default) | `"left"` (label column sized by `--component-form-label-width`)
- `size` — `"small"` | `"medium"` | `"large"`; propagated to controls and buttons
- `disabled` — boolean; disables all controls and buttons
- `loading` — boolean; submitting state — disables the buttons and shows a busy indicator without clearing values
- `loading-mode` — `"ring"` (default; indeterminate progress ring in the action row) | `"skeleton"` (skeleton placeholders replace the fields and their labels while loading)
- `novalidate` — boolean; skip built-in validation on submit
- `action` — optional native form action URL (progressive enhancement; when set and `y-submit` is not canceled, the native submit proceeds)
- `method` — `"get"` | `"post"` (default `"post"`), used when `action` is set
- `name` — form name

Property (not attribute): `values` — get/set current field values as `{name: value}` (checkbox/switch values are booleans). Setting merges by name; unknown keys are ignored. The getter reports the form's full state **including disabled fields**, so a form that disables its controls while saving still reports what it holds; native submission semantics (omitting disabled fields) apply to `formData` on `y-submit`, not to `values`.

Validation messages for `input` / `textarea` / `select` fields are handed to the control's own `error-text`, so the message lives in the same shadow root as the input and `aria-describedby` resolves. Other field types keep their message in the form's `field-error` live region and get `aria-invalid` shimmed onto their inner control.

Changing any attribute other than `fields` updates the existing tree in place — focus, caret position, IME composition, and open dropdowns survive a `loading` or `disabled` toggle mid-submit. Only `fields` rebuilds.

Slots: `header` (content above the fields), `actions` (replaces the default submit/reset row), `footer` (below the actions), plus one named outlet per `fields` entry with a `slot` key. Slotted form controls with a `name` participate in value collection, `y-change`, and validation.

Events:
- `y-submit` — `{values, formData}`; cancelable — call `preventDefault()` for async submission. Fired after validation passes.
- `y-reset` — cancelable; fired before fields are reset to their descriptor values.
- `y-change` — `{name, value, values}` when any field's value changes.
- `y-invalid` — `{invalid: [{name, message}]}` on failed submit validation; the first invalid control is focused.

Methods: `submit()`, `reset()`, `checkValidity()`

CSS Parts: `form`, `fields`, `header`, `actions`, `footer`, `submit-button`, `reset-button`
CSS Custom Properties: `--component-form-gap`, `--component-form-actions-gap`, `--component-form-actions-justify`, `--component-form-label-width`

```html
<!-- Generated fields -->
<y-form
  submit-text="Create account"
  fields='[
    {"type":"input","name":"username","label":"Username","required":true},
    {"type":"input","name":"email","label":"Email","inputType":"email","required":true},
    {"type":"select","name":"role","label":"Role","options":[{"value":"admin","label":"Admin"},{"value":"user","label":"User"}]},
    {"type":"switch","name":"newsletter","label":"Newsletter"}
  ]'
></y-form>

<!-- Interleaving a custom child via a named-slot entry -->
<y-form fields='[{"type":"input","name":"title","label":"Title"},{"slot":"extra"},{"type":"textarea","name":"notes","label":"Notes"}]'>
  <y-input slot="extra" name="attachment" placeholder="Attachment URL"></y-input>
</y-form>
```

```js
form.addEventListener("y-submit", async (e) => {
  e.preventDefault();               // handle async submission
  form.loading = true;
  await api.save(e.detail.values);  // or e.detail.formData
  form.loading = false;
});
```

### y-upload
Form-associated file upload with a drag-and-drop dropzone, client-side validation, and a managed file list with previews and per-file progress. Selected files submit with the parent form via `FormData` (each file under `name`). The component does not perform network uploads — the app handles transport and reports status back through `setProgress` / `setStatus`.

Tag: `<y-upload>`
Attributes:
- `name` — form field name; each selected file is appended to the form's `FormData` under this name
- `accept` — native `accept` syntax (comma-separated extensions and/or MIME types); enforced on both picker and drop
- `multiple` — boolean; allow more than one file. When absent, a new pick/drop replaces the current file
- `disabled` — boolean; disables the dropzone, picker, and remove buttons
- `required` — boolean; validation fails (`:invalid`) when no files are selected
- `max-files` — number; maximum file count (only meaningful with `multiple`). Excess files are rejected, not truncated
- `max-size` — number; maximum size per file, in bytes
- `max-total-size` — number; maximum combined size of all files, in bytes
- `variant` — `"dropzone"` (default; full drop target) | `"button"` (compact browse button; drop still accepted)
- `size` — `"small"` | `"medium"` | `"large"`
- `show-list` — boolean-like (`"false"` hides); render the managed file list beneath the dropzone (default on)
- `previews` — boolean; show image thumbnails (object URLs) for image files in the list
- `directory` — boolean; allow selecting a folder (`webkitdirectory`)

Property (not attribute): `files` — get/set the current `File[]`.
Read-only reflected attribute: `dragover` — present while a drag hovers the dropzone (for styling).

Validation order per file: `accept` → `max-size` → `max-files` → `max-total-size`. All rejections from one pick/drop batch into a single `reject` event; valid files from the same batch are still added. Duplicates (name + size + lastModified) are ignored silently.

Slots: default — dropzone prompt content (fallback: upload icon + "Drag files here or click to browse"); `icon` — replaces the default prompt icon.

Events:
- `change` — `{files: File[]}` when the list changes (add or remove)
- `reject` — `{rejections: {file, reason: "accept"|"max-size"|"max-files"|"max-total-size"}[]}`
- `remove` — cancelable; `{file}` before a file is removed via its list button — call `preventDefault()` to keep it

Methods: `browse()`, `clear()`, `setProgress(file, percent)`, `setStatus(file, status, message?)` where status is `"pending"|"uploading"|"done"|"error"`.

CSS Parts: `dropzone prompt icon file-list file file-name file-size file-preview file-progress file-error remove-button`
CSS Custom Properties: `--component-upload-border-color`, `--component-upload-border-color-dragover`, `--component-upload-background`, `--component-upload-background-dragover`, `--component-upload-border-radius`, `--component-upload-padding-{small|medium|large}`, `--component-upload-prompt-color`, `--component-upload-file-background`, `--component-upload-file-border-radius`, `--component-upload-progress-color`, `--component-upload-error-color`

```html
<y-upload name="docs" accept=".pdf,image/*" multiple max-size="5242880" previews></y-upload>
```

```js
// The app owns transport; report progress/status back to the row.
upload.addEventListener("change", async ({ detail }) => {
  for (const file of detail.files) {
    upload.setStatus(file, "uploading");
    await send(file, (pct) => upload.setProgress(file, pct));
    upload.setStatus(file, "done");
  }
});
```

### y-progress
Progress indicator. Renders as a horizontal bar (default), a circular ring, or a filled pie sector. Supports single-value or multi-value rendering — when a `values` array of 2+ entries is supplied, the bar stacks, the ring shows concentric arcs, and the pie renders multiple slices.

Tag: `<y-progress>`
Attributes:
- `mode` — `"bar"` (default) | `"ring"` | `"pie"`
- `value` — single numeric value. Deprecated when using multi-value rendering — use `values` instead. Falls back when `values` is unset or invalid.
- `values` — JSON array of `{ value, color?, label? }` entries. With ≥2 entries: `bar` stacks each entry as its own full-width row separated by `segment-gap` (only the top and bottom rows get outer rounding), `ring` renders concentric arcs (outer to inner), `pie` renders back-to-back slices from `start-angle`. Each entry's `color` overrides the host `color`; `label` is exposed via `title` (bar) or as a hover tooltip target.
- `min` — numeric (default `0`)
- `max` — numeric (default `100`)
- `step` — numeric, snaps `percentage` to step boundaries
- `size` — `"small"` | `"medium"` (default) | `"large"` or a raw length (e.g. `"160px"`). Bar thickness in `bar`, diameter in `ring`/`pie`.
- `thickness` — `"small"` | `"medium"` (default) | `"large"` or a raw length. Ring stroke width; ignored in `bar`/`pie`.
- `color` — predefined scheme (default `"primary"`) or any CSS color
- `track-color` — overrides the unfilled track / ring background; falls back to `--base-background-component`
- `label-display` — `"true"` (default) | `"false"`. In `ring`/`pie`, the label centers inside the shape.
- `label-format` — `"percent"` (default) | `"value"` | `"fraction"`
- `indeterminate` — boolean. `bar`: sliding strip. `ring`/`pie`: rotating partial arc.
- `disabled` — boolean. Reduces opacity, disables pointer events, sets `aria-disabled`.
- `segmented` — boolean (presence: auto count from `step` or default 10) or integer (explicit count, capped at 50). Splits the fill into discrete segments. Supported in `bar` and `ring`; ignored in `pie` and when multi-value.
- `segment-gap` — `"none"` | `"x-small"` (default) | `"small"` | `"medium"` or a raw length. Gap between segments.
- `start-angle` — degrees (clock convention: `0` = 12 o'clock, `90` = 3 o'clock). Default `0`. Also where the sweep ends since it's a full circle. Ignored in `bar`.
- `direction` — `"clockwise"` (default) | `"counterclockwise"`. Ignored in `bar`.

Slots:
- _(default)_ — header label rendered above the shape; hidden when empty.
- `center` — content rendered inside the ring/pie center, replacing the built-in value label. Ignored in `bar`.

Methods: `increment()`, `decrement()` — single-value only; mutate `value` by `step` (or 1) within `[min, max]`.

CSS Parts: `track`, `bar`, `value-label`, `segment`, `stack-row`, `ring`, `ring-track`, `ring-fill`, `pie`, `pie-track`, `pie-fill`, `center`.

CSS Custom Properties: `--component-progress-border-width`, `--component-progress-border-radius-outer`, `--component-progress-border-radius-inner`, `--component-progress-padding`, `--component-progress-size-small/medium/large`, `--component-progress-thickness-small/medium/large`, `--component-progress-segment-gap`, `--component-progress-track-color`, `--component-progress-label-size`.

Accessibility: each shape carries `role="progressbar"` with `aria-valuemin`/`aria-valuemax` and `aria-valuenow` (sum of `values` capped at `max` when multi-value). `aria-busy="true"` while `indeterminate`. The default-slot header is the implicit label; otherwise consumers should provide `aria-label` on the host.

```html
<!-- Single-value bar (back-compat) -->
<y-progress value="60" color="primary">Uploading…</y-progress>

<!-- Stacked bar -->
<y-progress
    values='[{"value":35,"color":"primary","label":"Photos"},{"value":22,"color":"success","label":"Apps"},{"value":18,"color":"warning","label":"Other"}]'
    label-display="false"
></y-progress>

<!-- Ring with custom center content -->
<y-progress mode="ring" value="78" size="140px">
    <span slot="center"><strong>78</strong> / 100</span>
</y-progress>

<!-- Concentric activity rings -->
<y-progress
    mode="ring" size="160px"
    values='[{"value":80,"color":"primary"},{"value":55,"color":"success"},{"value":30,"color":"warning"}]'
></y-progress>

<!-- Multi-slice pie -->

    mode="pie" size="140px"
```

### y-gauge
Radial gauge / dial. Draws a value on a circular arc — a KPI dial by default (neutral track, accent fill, big center number), an instrument dial with `needle`, colored zones, and a labeled scale. Everything is drawn in a fixed 200-unit viewBox scaled by the SVG, so marks and text stay crisp at any size; give the host a CSS width to size it.

Tag: `<y-gauge>`
Attributes:
- `value` — numeric. Defaults to `min`. Clamped into `[min, max]` for the arc; the center number shows the raw value.
- `min` — numeric (default `0`)
- `max` — numeric (default `100`)
- `start-angle` — arc start in degrees, clock convention (`0` = 12 o'clock, increasing clockwise). Default `225`.
- `end-angle` — arc end in degrees. Default `495` — a 270° sweep with the gap at the bottom. `start-angle="0" end-angle="360"` closes the dial into a full circle (the tick at `max` is dropped so it doesn't stack on the one at `min`).
- `thickness` — ring width as a fraction of the radius, clamped to `0.04`–`0.4` (default `0.16`)
- `progress` — `"true"` (default) | `"false"`. Fills the arc from `min` to `value`. With `ranges` set, the fill insets inside the zones so both stay legible.
- `needle` — boolean. Draws a pointer at `value`. Moves the value/label readout below the needle's sweep so the pointer never crosses the number.
- `target` — numeric. Renders a caret marker on the outside of the arc.
- `ranges` — array of `{ from, to, color }` zones painted onto the track (redlines, thresholds, bands). Set as a property or a JSON attribute. `color` accepts a CSS color literal or a `var(--token)` reference; the zone containing `value` also tints the fill and the center number unless `color` is set.
- `ticks` — number of major tick intervals around the arc (default `0` — none)
- `minor-ticks` — subdivisions between each pair of major ticks (default `0`)
- `tick-labels` — boolean. Labels each major tick with its value.
- `show-value` — `"true"` (default) | `"false"`. Toggles the center number.
- `label` — caption under the value (e.g. `"Speed"`)
- `unit` — appended to the value (e.g. `"%"`, `" mph"`, `" rpm"`)
- `decimals` — fractional digits in the center value, `0`–`6` (default `0`). Thousands are grouped by locale.
- `color` — accent for the fill and the center number, as a CSS color literal or a `var(--token)` reference. Overrides any range color.
- `loading` — boolean. Swaps the dial for a circular skeleton placeholder.
- `loading-text` — accessible label announced while `loading` (default `"Loading gauge…"`)

CSS Parts: `gauge`, `track`, `zone`, `progress`, `needle`, `needle-pointer`, `needle-hub`, `tick`, `tick-minor`, `tick-label`, `target`, `value`, `unit`, `label`, `skeleton`.

CSS Custom Properties: `--component-gauge-track-color`, `--component-gauge-value-color`, `--component-gauge-needle-color`, `--component-gauge-target-color`, `--component-gauge-tick-color`, `--component-gauge-tick-minor-color`, `--component-gauge-label-color`, `--component-gauge-skeleton-color`, `--component-gauge-value-size`, `--component-gauge-label-size`, `--component-gauge-tick-label-size`.

Accessibility: the dial carries `role="meter"` with `aria-valuemin`/`aria-valuemax`/`aria-valuenow` and an `aria-valuetext` of the formatted value plus its unit. `label` becomes the `aria-label` (falling back to `"Gauge"`) — supply one when the dial has no visible caption. The center text is `aria-hidden` so it isn't read twice. While `loading` the placeholder is `aria-busy` and announces `loading-text`. The fill and needle transitions respect `prefers-reduced-motion`.

```html
<!-- KPI dial -->
<y-gauge value="68" unit="%" label="Utilization" style="width: 220px"></y-gauge>

<!-- Against a target -->
<y-gauge value="72" target="90" unit="%" label="Quota" style="width: 220px"></y-gauge>

<!-- Threshold zones -->
<y-gauge id="health" value="84" unit="%" label="Health" style="width: 220px"></y-gauge>
<script>
    document.getElementById("health").ranges = [
        { from: 0, to: 30, color: "var(--error-content)" },
        { from: 30, to: 70, color: "var(--warning-content)" },
        { from: 70, to: 100, color: "var(--success-content)" },
    ];
</script>

<!-- Instrument dial: needle, no fill, labeled scale -->
<y-gauge
    value="55" min="0" max="120" unit=" mph"
    needle progress="false"
    ticks="12" minor-ticks="1" tick-labels
    style="width: 300px"
></y-gauge>

<!-- Semicircle: 9 o'clock to 3 o'clock -->
<y-gauge
    value="42" unit="%" label="Storage"
    start-angle="270" end-angle="450"
    style="width: 240px"
></y-gauge>

<!-- Loading -->
<y-gauge loading label="CPU load" style="width: 220px"></y-gauge>
```

### y-popover
Target-anchored, slot-based floating panel. Bridges `<y-tooltip>` (hover/focus text popups) and `<y-dialog>` (centered modal panels) — the primitive for rich, positioned popovers like confirmation prompts, action menus, combobox dropdowns, inline help, and any UI that points at an existing element without taking over the viewport. Used internally by `<y-help>` for its tour-step surface.

Tag: `<y-popover>`
Attributes:
- `open` — reflects whether the popover is currently visible. Toggle to show/hide.
- `anchor` — element `id` (no `#`) or CSS selector. Also accepts a direct `Element` reference via the property. If both unset and a `[slot="trigger"]` child is present, the trigger is used.
- `position` — `"auto"` (default) | `"top"` | `"bottom"` | `"left"` | `"right"` plus aligned variants (`"top-start"`, `"top-end"`, `"bottom-start"`, `"bottom-end"`, `"left-start"`, `"left-end"`, `"right-start"`, `"right-end"`). `"auto"` walks `bottom → top → right → left`; an explicit side tries `requested → opposite → perpendiculars`.
- `offset` — pixel gap between the anchor and the popover (default `8`).
- `pointer` — render the arrow that visually attaches the popover to the anchor (default `true`; set `pointer="false"` to hide).
- `trigger` — space-separated list of activation modes: any subset of `"click"`, `"hover"`, `"focus"`, `"context-menu"`, `"manual"`. Default `"manual"` — only `show()` / `hide()` / `open` attribute control visibility. Combine modes with `trigger="click hover focus"`.
- `delay-show` / `delay-hide` — milliseconds before opening / closing on hover or focus (default `0`).
- `modal` — when set, applies `role="dialog"` + `aria-modal="true"`, traps focus inside the popover, and forces Escape to always close. Off by default.
- `show-backdrop` — render the dim backdrop. Implicitly `true` when `modal` is set unless `show-backdrop="false"` is passed. Defaults to off otherwise.
- `close-on-escape` — defaults to `true`. Modal popovers honor Escape regardless of this attribute.
- `close-on-outside-click` — defaults to `true`. Clicks outside the popover *and* outside the anchor close it.
- `close-on-anchor-click` — defaults to `false`. When `true`, clicking the anchor again toggles the popover closed (otherwise the `"click"` trigger only opens).
- `portal` — render the surface out of the popover to escape ancestor stacking / transform / clip-path / overflow contexts. Off by default. The surface mounts into the nearest enclosing `<y-theme>` (falling back to `document.body`), so it keeps the active theme; CSS variables set on intermediate ancestors between the popover and the `<y-theme>` are not inherited.
- `text` — simple text content for the body. Equivalent to slotting a `<span>` into the default slot — provides a migration path from `<y-tooltip>`'s `text` attribute.
- `color` — `"base"` (default) | `"primary"` | `"secondary"` | `"success"` | `"warning"` | `"error"` | `"help"` or any safe CSS color literal (`#hex`, `rgb()`/`rgba()`, `hsl()`/`hsla()`).
- `size` — `"small"` | `"medium"` (default) | `"large"`.
- `disabled` — all triggers become inert; programmatic `show()` is a no-op; an open popover closes.

Slots:
- default — body content (falls back to the `text` attribute when empty)
- `trigger` — optional. When present, this child becomes the anchor automatically and trigger listeners attach to it.
- `header` — optional title row, divider rendered below.
- `footer` — optional action row, divider rendered above. Typical home for confirm/cancel buttons.
- `pointer` — override the default pointer/arrow with custom markup.

Events (bubble + composed; cancelable events have `cancelable: true`):
- `popover-open` — cancelable. `detail: { trigger: "click" | "hover" | "focus" | "context-menu" | "manual" }`.
- `popover-opened` — non-cancelable. Fired after positioning. `detail: { position }` reports the side it actually landed on after flip.
- `popover-close` — cancelable. `detail: { reason: "user" | "escape" | "outside" | "anchor-click" | "blur" | "api" }`.
- `popover-closed` — non-cancelable. `detail: { reason }`.
- `popover-anchor-change` — non-cancelable. `detail: { from, to }`.

Methods:
- `show(detail?)` → `Promise<boolean>` — open the popover; resolves `false` if cancelled or already open. Awaits one frame after positioning so callers can read `getBoundingClientRect` synchronously after.
- `hide(reason = "api")` → `Promise<boolean>` — close with the given reason.
- `toggle()` → `Promise<boolean>` — flip state.
- `updatePosition()` → resolved side or `null` — recompute position immediately. Use after content size changes the observers might miss.
- `setAnchor(element | selector)` — programmatic anchor change. Fires `popover-anchor-change`.

CSS Parts: `surface`, `header`, `body`, `footer`, `pointer`, `backdrop`, `trigger`.

Accessibility:
- Non-modal popovers use `role="tooltip"`; modal popovers use `role="dialog"` + `aria-modal="true"`.
- Header (when present) is referenced via `aria-labelledby`; the body is referenced via `aria-describedby`.
- The anchor receives `aria-describedby="<popover-id>"` while the popover is open.
- Modal mode focuses the first focusable inside the popover on open (drilling into custom-element shadow roots) and restores focus on close. Tab cycles within the popover boundary.
- Non-modal mode does not move focus; focus restoration only fires when focus was inside the popover at close time.
- Escape closes when `close-on-escape` is on (always for modal).
- Respects `prefers-reduced-motion` — disables enter/exit transitions when set.

CSS Custom Properties: `--component-popover-background`, `--component-popover-color`, `--component-popover-border-color`, `--component-popover-border-width`, `--component-popover-border-radius`, `--component-popover-padding-{small,medium,large}`, `--component-popover-font-size-{small,medium,large}`, `--component-popover-max-width`, `--component-popover-min-width`, `--component-popover-shadow`, `--component-popover-offset`, `--component-popover-pointer-size`, `--component-popover-pointer-color`, `--component-popover-pointer-border-color`, `--component-popover-backdrop`, `--component-popover-backdrop-blur`, `--component-popover-z-index`, `--component-popover-header-divider-color`, `--component-popover-transition-duration`.

```html
<!-- Click-triggered popover with rich content -->
<button id="save-btn">Save layout</button>
<y-popover anchor="save-btn" trigger="click" position="bottom">
    <strong slot="header">Confirm change</strong>
    <p>Saving will overwrite the existing layout.</p>
    <div slot="footer">
        <y-button size="small" variant="outlined">Cancel</y-button>
        <y-button size="small" color="primary">Save</y-button>
    </div>
</y-popover>

<!-- Hover tooltip-style popover -->
<y-popover trigger="hover focus" text="Helpful description" position="top">
    <y-button slot="trigger">Hover me</y-button>
</y-popover>

<!-- Modal confirmation popover, anchored to the trigger -->
<y-popover id="confirm" anchor="delete-btn" modal>
    <strong slot="header">Delete this item?</strong>
    <p>This action cannot be undone.</p>
    <div slot="footer">
        <y-button onclick="confirm.hide('user')">Cancel</y-button>
        <y-button color="error" onclick="confirm.hide('user')">Delete</y-button>
    </div>
</y-popover>
```

Notes:
- Positioning uses a flip-and-shift strategy: try the requested side → opposite → perpendiculars; cross-axis shift keeps the popover in view but is skipped entirely when the anchor itself is off-screen. Best-fit fallback when no side fits (pointer hidden).
- Detects transformed/filtered/clip-pathed ancestors and adjusts coords so `position: fixed` still lands on the viewport correctly (Storybook docs, animated panels, etc.).
- `portal="true"` moves the surface (plus backdrop and slotted body/header/footer children) into a `<div class="y-popover-portal">` appended to the nearest enclosing `<y-theme>` (so it inherits the theme), falling back to `<body>` when there is no `<y-theme>` ancestor. The trigger stays in place.
- Detached or removed anchors during the open lifecycle re-resolve on every reposition.
- Body / header / footer content is rendered as DOM (slotted), not via `textContent`, so consumers can put rich markup in slots.

### y-droplist
Drag-and-drop reorderable list with optional cross-list group support, drag handles, swap mode, and clone mode.

Tag: `<y-droplist>`
Attributes:
- `disabled` — boolean. Removes `draggable` from all items, sets `aria-disabled` on the host, and ignores keyboard reorder shortcuts.
- `vertical` — default reorders along the vertical axis. Set `vertical="false"` to reorder horizontally.
- `animation` — settle-animation duration in ms (default `150`). `0` disables. Honors `prefers-reduced-motion: reduce` regardless of value.
- `scroll` — boolean (default `true`). Auto-scrolls the nearest scrollable ancestor (or `window`) when the cursor is within `scroll-sensitivity` pixels of its edge during a drag. Set `scroll="false"` to disable.
- `scroll-sensitivity` — number (px, default `30`). Distance from the scroll-container edge at which auto-scroll engages. Invalid values fall back to `30`.
- `scroll-speed` — number (px/frame, default `10`). Per-frame scroll delta; clamped internally to `30`. Halved automatically when `prefers-reduced-motion: reduce` is active. Invalid values fall back to `10`.
- `revert` — boolean (default `false`). When present, items dropped outside any valid drop target animate back to their original positions using FLIP. `drag:end` fires after the animation completes. Without `revert`, a cancel is silent (item stays put, `drag:end` fires immediately).
- `force-float` — boolean (default `false`). When present, the ghost placeholder is appended to `document.body` with `position: fixed` so it floats above `overflow: hidden` containers and all stacking contexts. Ghost remains `aria-hidden`.
- `delay` — number (ms, default `0`). Delay before a press becomes a drag. The drag starts only if the pointer remains within `touch-start-threshold` pixels for the duration. `0` means the drag starts immediately on `pointerdown` (for touch/pen) or `dragstart` (for mouse with no effective delay).
- `delay-on-touch-only` — boolean (default `false`). When present, `delay` applies only to touch/pen pointer types; mouse presses bypass the delay and fall through to native HTML5 DnD.
- `touch-start-threshold` — number (px, default `0`). Maximum pointer movement allowed during the `delay` window. If the pointer moves further than this before the timer fires, the pending drag is cancelled. `0` disables threshold checking.
- `ghost-class` — CSS class applied to the placeholder shown at the projected drop position. Default `"y-droplist__ghost"`.
- `drag-class` — CSS class applied to the dragged item. Default `"y-droplist__dragging"`.
- `swap-class` — CSS class applied to the active swap target while dragging in swap mode. Default `"y-droplist__swap-target"`.
- `drag-preview` — boolean (default `false`). When present, a cursor-following clone of the dragged item is rendered in `document.body` during the drag. Distinct from the in-list ghost placeholder — both can be active simultaneously.
- `drag-preview-class` — CSS class applied to the preview element. Default `"y-droplist__drag-preview"`.
- `drag-preview-offset` — `"cursor"` (default) | `"center"` | `"top-left"`. Controls where the preview anchors relative to the cursor. `"cursor"` preserves the grab offset captured at drag start; `"center"` centers the preview on the cursor; `"top-left"` pins the cursor to the top-left corner.
- `drag-preview-scale` — number (default `1`). Scale factor applied via `transform: scale()` to the preview element. Use `< 1` for a shrunken card effect.
- `group` — string. Lists with the same `group` name can exchange items via drag-and-drop. Empty / unset means within-list only.
- `pull` — `"true"` (default) | `"clone"` | `"false"`. Controls whether items leave this list. `"true"` moves the item; `"clone"` leaves the original in place and inserts a copy in the destination; `"false"` blocks dragging out.
- `put` — `"true"` (default) | `"false"` | comma-separated group-name list. Controls whether items can be dropped into this list. `"true"` accepts any same-group item; `"false"` rejects all incoming; a group-name list restricts accepted sources to those whose `group` appears in the list.
- `handle` — CSS selector. When set, drags only initiate from elements within each item that match this selector. Empty (default) keeps the whole item draggable. Invalid selectors `console.warn` and fall back to whole-item.
- `prevent-on-filter` — boolean (default `true`). When `handle` is set, calls `preventDefault()` on `pointerdown` events outside the handle to suppress text selection. No-op when `handle` is empty.
- `swap` — boolean. When present, dropping over an item swaps the two items in place rather than inserting between items. Same-list only; cross-list drops fall through to insert mode. Disabled when `clone` is also set (clone wins).
- `invert-swap-element` — boolean (default `true`). In `swap` mode, controls swap-target selection: `true` picks the item the cursor is currently over; `false` picks the item whose midpoint the cursor has crossed.
- `clone` — boolean. When present, drops insert a `cloneNode(true)` copy at the drop position; the original stays at its source index. Composes with `pull="clone"` (which is the cross-list-source equivalent).

Events (bubble + composed):
- `drag:start` — `{ originalEvent, item, list }` — not cancelable.
- `drag:end` — `{ originalEvent, item, list }` — not cancelable. Always fires; `originalEvent` is the native dragend.
- `drag:enter` — `{ originalEvent, item, list, from }` — not cancelable. Fired on the **destination** list when a foreign item first enters its hit area. `from` is the source list. Only fires when the two lists are compatible (same group, pull/put allow).
- `drag:leave` — `{ originalEvent, item, list, to }` — not cancelable. Fired on the **source** list when the dragged item leaves its bounds. `to` is the destination list, or `null` if the cursor left all droplists.
- `drag:preview` — `{ item, preview, list }` — **cancelable**. Fired after the preview element is created and styled but **before** it is appended to `document.body`. Calling `preventDefault()` cancels preview creation for this drag session — the element is discarded and never enters the DOM. Consumers may mutate `detail.preview` to alter content or add classes; mutations apply before insertion. Because the preview is detached when the event fires, do not rely on `getBoundingClientRect()` or `offsetParent` inside the handler.
- `drag:move` — `{ originalEvent, item, list, x, y }` — not cancelable. Throttled to one event per `requestAnimationFrame`. Fires on every `dragover` / `pointermove` while a drag is active. `x` and `y` are the current viewport cursor coordinates.
- `drag:over` — `{ originalEvent, item, list, target }` — not cancelable. Fires only when the cursor transitions to hover a **different** slotted child (`target`) than on the previous tick. Does not re-fire when the cursor stays over the same item.
- `drag:drop` — `{ originalEvent, item, list, index }` — not cancelable. Fires **before** the DOM mutation on a successful drop. `index` is the projected insertion index (0-based).
- `reorder` — `{ oldIndex, newIndex, item, list[, from] }` — not cancelable. Fires only when index changes. On a cross-list drop `oldIndex` is `-1` and `from` is the source list. On a `swap` drop, `oldIndex` and `newIndex` describe the two swapped items. On a same-list `clone` drop, `oldIndex` is `-1` and `item` is the inserted clone.
- `update` — `{ item, oldIndex, newIndex, list[, from] }` — not cancelable. Fires immediately after `reorder`. On a cross-list drop the **source** fires first with `newIndex: -1`; the destination fires next with the insert position. On a same-list `clone` drop only the destination event fires (source is suppressed).

Methods:
- `toArray()` — returns each direct child's `data-id` (or `""` if missing) in current DOM order.
- `hasItem(item)` — true when `item` is a direct slotted child of the droplist.
- `destroy()` — removes all listeners, the mutation observer, and unregisters from the cross-list group registry. The component re-initializes on disconnect/reconnect.
- `sort(compareFn?)` — sorts all slotted children in place. The default comparator compares each child's `data-id` using `<` / `>` semantics (plain lexicographic/ASCII-style ordering, not `localeCompare`). Fires a single `update` event with `{ oldIndex: -1, newIndex: -1 }`. Pass a custom `(a, b) => number` comparator for custom order.
- `option(name, value?)` — get or set the component property corresponding to a kebab-case option name (mapped to camelCase). One argument returns the current property value; two arguments assigns that property. Depending on the property, this may return non-string values and may reflect to, update, or remove the underlying attribute.
- `closest(evt)` — returns the direct slotted child whose bounding rect contains `evt.clientX`/`evt.clientY`, or `null` if none match.

Behavior:
- Items get `role="listitem"`, `tabindex="0"`, `draggable="true"`, and `aria-grabbed="false"` automatically; new children added at runtime are auto-initialized via `MutationObserver`.
- Keyboard reorder: focus an item, press `ArrowUp`/`ArrowDown` (or `ArrowLeft`/`ArrowRight` when `vertical="false"`). Focus stays on the moved item; `reorder` and `update` fire identically to a mouse drop. When `handle` is set, focus may be on the handle element; keydown still works via bubbling and focus stays on the handle.
- A polite `aria-live` region inside the shadow root announces moves. Within-list: _"Item moved from position X to position Y."_ Cross-list: _"Item moved to list `<aria-label>` at position N."_, falling back to _"another list"_ when the destination has no accessible name. Swap mode: _"Item swapped with position N."_ Clone: _"Item copied to position N."_ (or _"Item copied to list `<label>` at position N."_ for cross-list).
- Settle animation uses FLIP. Skipped when `animation="0"` or `prefers-reduced-motion: reduce`. Swap mode skips FLIP since the two affected items jump directly.
- Cross-list compatibility is checked on every `dragover`. Incompatible combinations do not call `preventDefault()`, so the OS shows the "not allowed" cursor and no ghost appears.
- `handle` mode: items get `tabindex="-1"` and the first matching descendant element gets `tabindex="0"` (only when the descendant doesn't already have a tabindex). On `pointerdown` outside the handle, `draggable` is flipped to `false` until `pointerup` / `pointercancel`, blocking the native drag from starting.
- `clone` overrides `swap` when both are set on the same list — the drop performs a clone insert and the swap indicator never appears.
- **Touch / pointer pipeline**: Touch and pen input uses `pointerdown` / `pointermove` / `pointerup` with `setPointerCapture`. `touch-action: none` is applied to the press target (the item, or the handle element when `handle` is set) at decoration time — before any touch begins — so mobile browsers do not preempt the press as a scroll gesture. It is cleared only when the list is disabled or the handle selector changes. Mouse presses with no effective delay defer to native HTML5 DnD. Cross-list touch drops use bounding-box hit-testing via `getBoundingClientRect`. `originalEvent` in `drag:start` / `drag:end` is the originating `PointerEvent` for touch drags. Supported: iOS Safari 14+, Chrome Android 90+, desktop Chromium / Firefox / Safari latest two majors.
- Auto-scroll uses a shared `requestAnimationFrame` loop (one loop across all `<y-droplist>` instances). The scroll container is found by walking up from the hovered list via `getComputedStyle(...).overflow` and is cached per-drag on the source list. Scrolling stops on `dragend`.
- `revert` shares `--component-droplist-transition-duration` / `--component-droplist-transition-easing` with the settle animation. With `prefers-reduced-motion: reduce`, the items snap back without easing and `drag:end` fires immediately.
- `force-float` ghost inlines its own styles (background/border/opacity via CSS custom properties that cascade from `:root`). The `::slotted([data-y-droplist-ghost])` shadow rule does not apply to it. The insertion position is tracked internally per-drop so the item is inserted at the correct index on drop.

Slots: default (slotted items). `drag-preview` — optional; when present, the slotted element is deep-cloned and used as the preview content instead of cloning the dragged item. The original is hidden during the drag and restored on drop.

CSS Parts: `list` (the shadow-DOM wrapper around the slot). The drag preview element carries `part="drag-preview"` but is appended to `document.body` (outside the shadow root), so `::part(drag-preview)` cannot match it — see "Styling the drag preview" below for workable selectors.

Styling items: list items are slotted light-DOM children, so style them with regular descendant selectors (`y-droplist > *`, `y-droplist > .y-droplist__dragging`, etc.) — `::part()` doesn't reach light DOM.

Ghost vs. preview: the ghost (`[data-y-droplist-ghost]`) is the in-list dashed placeholder that shows where the item will land. The drag preview (enabled via the `drag-preview` attribute) is the cursor-following visual clone rendered in `document.body`. Both can be active simultaneously. Safari may show its native drag image alongside the custom preview because it ignores `setDragImage` — a known Safari limitation.

Styling the ghost placeholder: target it via the `[data-y-droplist-ghost]` attribute selector, the class set by the `ghost-class` attribute (default `.y-droplist__ghost`), or the `--component-droplist-ghost-*` custom properties below.

Styling the drag preview: target the class set by `drag-preview-class` (default `.y-droplist__drag-preview`), the `[part="drag-preview"]` attribute selector, or the `--component-droplist-drag-preview-*` custom properties. Note: `::part(drag-preview)` does **not** work because the preview is rendered in `document.body`, not inside the shadow root — use the class or attribute selector instead.

CSS Custom Properties: `--component-droplist-ghost-opacity`, `--component-droplist-ghost-background`, `--component-droplist-ghost-border-color`, `--component-droplist-item-padding`, `--component-droplist-item-margin`, `--component-droplist-empty-min-height` (default `40px`; drop area reserved when the list is empty and can receive items from its group, so an emptied column remains a drop target — empty lists with no `group` or with `put="false"` stay collapsed), `--component-droplist-transition-duration` (override the `animation` attribute), `--component-droplist-transition-easing`, `--component-droplist-swap-indicator-background` (background applied to the active swap target), `--component-droplist-handle-color` and `--component-droplist-handle-size` (convenience tokens consumers can use to style their own handle elements; not used internally), `--component-droplist-drag-preview-opacity` (default `0.85`), `--component-droplist-drag-preview-shadow` (defaults to the theme-wide `--base-shadow` when unset; if `--base-shadow` is also unset, falls back to the hard-coded `0 4px 12px rgba(0,0,0,0.15)`), `--component-droplist-drag-preview-rotate` (default `0deg`; set e.g. `2deg` for a tilt), `--component-droplist-drag-preview-cursor-offset-x` / `--component-droplist-drag-preview-cursor-offset-y` (additive px offsets from the cursor anchor), `--component-droplist-drag-preview-z-index` (default `9999`).


### y-menu
Dropdown menu. Positioned relative to an anchor element. Items can be defined via the `items` JSON attribute or as light-DOM children.

Tag: `<y-menu>`
Attributes:
- `items` — JSON string: `[{"text": "Edit", "value": "edit", "href": "...", "icon": "pencil", "slot": "name", "selected": true, "children": [...]}, ...]`
- `anchor` — element ID (no `#`) of the trigger element; clicking the anchor toggles the menu automatically (no manual listener needed). A disabled anchor (native `disabled`, a reflected `disabled` attribute on a custom element like `y-button`, or `aria-disabled="true"`) will not open the menu.
- `visible` — boolean
- `direction` — `"down"` (default) | `"up"` | `"left"` | `"right"`
- `size` — `"small"` | `"medium"` | `"large"`
- `history` — omit (default) for SPA `pushState` navigation; `"false"` for full-page `window.location.href`

Events:
- `open` — fires when the menu becomes visible
- `close` — fires when the menu is dismissed
- `select` — fires when a leaf item is activated. `event.detail = { value, item?, element? }`. `item` is set for JSON-defined items; `element` is set for slotted children.
- `navigate` — cancelable; `event.detail.href`. Fires before navigation when an item with `href` is clicked.

- `text` — display text
- `value` — value reported in the `select` event (defaults to `text`)
- `href` — optional navigation URL
- `icon` — icon name rendered via `<y-icon>` (e.g. `"pencil"`, `"trash"`)

- `icon-template` — use `icon`
- `template` — use `slot`

### y-help
Guided product-tour / onboarding overlay. Given an ordered list of steps, dims the page, highlights one or more targeted elements per step (single SVG mask for clean multi-target cutouts), and anchors a tooltip with helper text to them. Steps without a target render a centered tooltip for general messages. Users advance with prev/next, large overlay-edge arrows, or arrow-key shortcuts until the tour completes or they dismiss it.

Tag: `<y-help>`
Attributes:
- `steps` — `HelpStep[]` (property; also accepts a JSON string via attribute). Each step: `{ target?: string | string[], title?: string, content: string, position?: "top" | "bottom" | "left" | "right" | "center" | "auto", anchor?: "bounds" | "first" | "last" | number, highlightPadding?: number }`. `target` is either an element `id` (no `#`) or a CSS selector, or an array of either.
- `open` — reflects whether the tour is active. Toggling it starts / stops the tour.
- `index` — 0-based active step index. Reflected.
- `default-position` — `"auto"` (default) | `"top"` | `"bottom"` | `"left"` | `"right"` | `"center"`. Used when a step does not specify `position`.
- `untargeted-position` — `"center"` (default) | other positions. Used when a step has no `target` or none of its targets resolve.
- `default-anchor` — `"bounds"` (default) | `"first"` | `"last"` | numeric index. Multi-target anchor when a step does not specify `anchor`.
- `highlight-padding` — number (px, default `8`). Pixel padding around each highlighted element. Overridable per step via `highlightPadding`.
- `show-progress` — defaults to `true`. Shows "N of M" inside the tooltip.
- `show-arrows` — defaults to `true`. Renders large prev/next arrow buttons on the overlay edges in addition to the tooltip controls.
- `close-on-escape` — defaults to `true`. Pressing Escape closes the tour.
- `close-on-overlay-click` — defaults to `false`. Clicking the dim area closes the tour.
- `disable-target-interaction` — defaults to `true`. When `false`, highlighted elements remain clickable; the rest of the page is still blocked.
- `prev-label` / `next-label` / `finish-label` / `close-label` — control button text (`finish-label` is shown on the next button on the last step when `loop` is unset).
- `loop` — when present, advancing past the last step returns to the first instead of firing `y-help-complete`.

Slots: none in v1. y-help is fully programmatic — step title/content come from each step object's `title` / `content` fields, and button text comes from the `prev-label` / `next-label` / `finish-label` / `close-label` attributes. Per-region slot overrides and declarative `<y-help-step>` children are planned for a future release; consumers needing rich step content today can style the existing rendering via the documented CSS parts.

Events (bubble + composed):
- `y-help-open` — cancelable. Fired before the tour opens. `detail: { index }`.
- `y-help-start` — non-cancelable. Fired after the first step renders. `detail: { index, step }`.
- `y-help-step-change` — cancelable. Fired before moving between steps. `detail: { from, to, step, direction: "next" | "prev" | "goto" }`. Cancelling lets authors gate progression on an external action.
- `y-help-complete` — non-cancelable. Fired when the user advances past the last step (only when `loop` is unset). `detail: { totalSteps }`.
- `y-help-close` — cancelable. Fired before the tour closes. `detail: { index, reason: "user" | "escape" | "overlay" | "complete" | "api" }`.

Methods: `start(index = 0)`, `next()`, `prev()`, `goto(index)`, `close(reason = "api")`. Methods other than `start` are no-ops when the tour isn't open.

CSS Parts: `overlay`, `highlight` (every cutout in a multi-target step receives this part), `tooltip`, `tooltip-title`, `tooltip-content`, `tooltip-actions`, `prev-button`, `next-button`, `close-button`, `progress`, `arrow-prev`, `arrow-next`, `pointer`.

Accessibility:
- The tooltip is `role="dialog"` with `aria-modal="true"`, linked to title/content via `aria-labelledby` / `aria-describedby`.
- Buttons carry aria-labels from `prev-label` / `next-label` / `close-label`. Progress is `aria-live="polite"`.
- Focus is captured into the tooltip on open and restored to the previously-focused element on close. Tab cycles within the tooltip's interactive controls.
- Arrow keys advance/retreat; Enter advances; Escape closes (when `close-on-escape` is on).
- Respects `prefers-reduced-motion` — disables transitions when set.

CSS Custom Properties (exhaustive — every variable y-help actually reads): `--component-help-overlay-bg`, `--component-help-overlay-z-index`, `--component-help-highlight-border-radius`, `--component-help-highlight-outline-color`, `--component-help-highlight-outline-width`, `--component-help-highlight-shadow`, `--component-help-tooltip-bg`, `--component-help-tooltip-color`, `--component-help-tooltip-border-color`, `--component-help-tooltip-border-radius`, `--component-help-tooltip-padding`, `--component-help-tooltip-max-width`, `--component-help-tooltip-shadow`, `--component-help-tooltip-offset`, `--component-help-arrow-size`, `--component-help-nav-arrow-size`, `--component-help-nav-arrow-bg`, `--component-help-nav-arrow-bg-hover`, `--component-help-nav-arrow-color`.

```html
<button id="launch">Take the tour</button>
<y-help id="tour"></y-help>

<script type="module">
    const help = document.getElementById("tour");
    help.steps = [
        { target: "btn-create", title: "Start here", content: "Spin up a new agent." },
        { target: ["card-1", "card-2"], anchor: "bounds", content: "Each agent gets a card." },
        { title: "All set!", content: "You can replay this any time from Settings." },
    ];
    document.getElementById("launch").addEventListener("click", () => help.start());
</script>
```

Notes:
- The overlay and tooltip are portaled out of `<y-help>` (so they escape ancestor `overflow` / `transform` / `z-index` contexts) into the nearest enclosing `<y-theme>`, falling back to `document.body` when there is no `<y-theme>` ancestor. Mounting inside the theme is deliberate: YumeKit themes are CSS custom properties scoped to the `<y-theme>` subtree, so a `document.body`-level overlay would render with the un-themed default palette. **Put `<y-help>` inside your `<y-theme>`** and the tour matches the active theme automatically (including live theme switches). The overlay is `position: fixed`, so it still covers the viewport regardless of where it mounts.
- Tooltip positioning uses a flip-only collision strategy in v1: try the requested side, fall back to the opposite, then `bottom` / `top` / `right` / `left`. Untargeted tooltips center in the viewport.
- Persistence ("has the user seen this tour?") is the caller's responsibility — read/write storage and pass `open`/`index` accordingly.
- Step `content` and `title` are rendered via `textContent` and never re-parsed as HTML. For rich content, use the `content` / `title` slots or wait for `<y-help-step>` in a future release.

### y-money
Currency input. Form-associated. Shows a locale-formatted amount when idle (`$1,234.56`) and a plain editable number while focused (`1234.56`), and submits a canonical decimal string. Prefer this over `<y-input type="number">` for any monetary amount.

Tag: `<y-money>`
Attributes:
- `value` — canonical decimal string, e.g. `"1234.56"`. Always `.` as the decimal separator and no grouping, whatever the locale. `""` means no value, which is distinct from `"0"`.
- `currency` — ISO 4217 code (default `"USD"`). Drives the symbol and the default precision. An unknown code falls back to `USD` with a console warning.
- `locale` — BCP 47 tag; omitted means the browser locale. Controls separators, grouping, and symbol placement.
- `precision` — decimal places. Defaults to the currency's exponent (USD 2, JPY 0, KWD 3).
- `display` — `"symbol"` (default, `$1,234.56`) | `"code"` (`USD 1,234.56`) | `"name"` (`1,234.56 US dollars`) | `"none"` (bare `1,234.56`)
- `allow-negative` — boolean. Without it a typed `-` is rejected and a negative assigned in code clamps to zero.
- `negative-style` — `"minus"` (default, `-$5.00`) | `"parentheses"` (`($5.00)`). Editing always uses a minus.
- `step` — arrow-key increment as a decimal string (default `"1"`, one whole currency unit)
- `min`, `max` — decimal-string bounds. A violation flags the field invalid; the entry is left as typed rather than silently clamped.
- `name` — form field name
- `placeholder`
- `size` — `"small"` | `"medium"` (default) | `"large"`
- `variant` — `"default"` (full border) | `"underline"` (bottom border only, square bottom corners)
- `label-position` — `"top"` (default) | `"bottom"`
- `disabled` — boolean
- `required` — boolean, empty value fails validation
- `invalid` — boolean, applies error state
- `error-text` — validation message rendered below the field; also applies the error state and becomes the accessible description
- `autocomplete` — forwarded to the inner control

Properties (JS only, read-only): `valueAsNumber` (float, `NaN` when empty), `valueAsMinorUnits` (integer minor units — `1234.56` → `123456`, derived with integer math, `NaN` when empty), `formattedValue` (the idle display string), `validity`, `validationMessage`.

Methods: `stepUp(n = 1)` / `stepDown(n = 1)` increment by `step` clamped to `min`/`max`; `checkValidity()`; `reportValidity()`.

Slots: `label`, `left-icon`, `right-icon`.

Events: `input` (detail `{ value, valueAsNumber }`) on each accepted keystroke — `value` may be a partial entry such as `"12."`; `change` (same detail) on commit, meaning blur after an edit, Enter, or a step. Setting `value` in code fires neither. Both bubble and are composed.

Accessibility: the inner control is `<input type="text" inputmode="decimal">` — not `type="number"`, which forbids grouping separators and reports `""` for a partially-typed value. `aria-label` / `aria-labelledby` on the host are forwarded to it. Up/Down arrows step the value.

CSS Custom Properties: inherits the shared field tokens (`--component-input-background`, `--component-input-border-color`, `--component-input-accent`, `--component-input-error-color`, `--component-inputs-border-width`, `--component-inputs-border-radius-outer`, …) so it sits flush with `y-input`. Adds `--component-money-negative-color` for the idle color of negative amounts (defaults to `--error-content`).

CSS Parts: `input`, `error-text`.

Behavior notes: values round half-away-from-zero at `precision` using digit arithmetic, so `1.005` → `1.01` rather than the float result. Formatting hands the decimal string to `Intl.NumberFormat` directly, so amounts past float safety keep every digit. Pasting scrubs currency symbols and grouping separators, so `"$1,234.56"` yields `1234.56`. Grouping-as-you-type is deliberately not done — the field reformats on blur so the caret is never moved mid-edit. All of this lives in `@waggylabs/yumekit/modules/money.js` (see _Public Modules_), so a component that displays an amount without collecting one shares the rounding and formatting rather than re-deriving them.

```html
<y-money name="price" currency="USD" value="1234.56" required>
  <span slot="label">Price</span>
</y-money>

<y-money name="balance" currency="EUR" locale="de-DE" allow-negative negative-style="parentheses"></y-money>
```

### y-paginator
Page navigation control with configurable button window, ellipsis collapsing, prev/next, an optional items-per-page select, and SPA-friendly cancelable events. Page buttons are rendered as `y-button` (flat for inactive, filled primary for the active page).

Tag: `<y-paginator>`
Attributes:
- `current-page` — currently active page (1-indexed). Clamped to `[1, total-pages]` when `total-pages >= 1`, and reports `0` when `total-pages = 0` (no-data state). Default `1` (or `0` when there is no data).
- `total-pages` — total number of pages. `0` indicates no data; in that state the page list is omitted and `current-page` reads as `0`. Default `0`.
- `page-count` — maximum page buttons displayed at once, excluding ellipses. Default `5`. The rendered count auto-shrinks to fit narrower host widths and grows back up to this maximum as space allows.
- `boundary-count` — number of pages always shown at each end. Default `1`.
- `variant` — `"default"` (default — page-number buttons with prev/next), `"compact"` (first / prev / "n of n pages" status / next / last; no page list), or `"detailed"` (default layout plus prev/next text labels).
- `size` — `"small"` | `"medium"` (default) | `"large"`. Forwarded to the page `y-button`s and the items-per-page `y-select`.
- `disabled` — boolean. Disables every interactive control.
- `hide-on-single-page` — defaults to `true`. The component hides itself when `total-pages <= 1` *and* there is no items-per-page select to show. Pass `hide-on-single-page="false"` to always render.
- `items-per-page` — currently selected items-per-page value (number).
- `page-size-options` — JSON array of numbers (`[10, 25, 50]`) or `[{value, label}]` objects. When set, an items-per-page `<y-select>` is appended after the navigation wrapper (i.e., to the right of the page list, wrapping below on narrow widths).
- `page-size-label` — label text shown next to the select; only visually rendered when `variant="detailed"`, otherwise applied as the select's `aria-label`. Default `"Items per page:"`.

Events (cancelable, bubble + composed):
- `page-change` — `{ page }`. Calling `preventDefault()` aborts the page transition.
- `update:current-page` — `{ page }`. Fires after `page-change` for two-way-binding consumers; cancelling it also aborts.
- `page-size-change` — `{ pageSize, previous }`. Cancellation reverts the select to the prior value.
- `update:items-per-page` — `{ pageSize, previous }`. Mirror event for v-model-style consumers.

Methods: `goTo(page)`, `next()`, `previous()`, `setPageSize(value)`.

Slots: `prev-label`, `next-label` (override the prev/next button content; only rendered when `variant="detailed"`), `ellipsis` (override the `…` glyph).

CSS Parts: `wrapper`, `nav-wrapper`, `list`, `button`, `button--active`, `button--disabled`, `nav-first`, `nav-prev`, `nav-next`, `nav-last`, `compact-status`, `ellipsis`, `page-size`, `page-size-label`, `page-size-select`. (`nav-first` / `nav-last` / `compact-status` only appear when `variant="compact"`.)

Keyboard: while focus is on a page `y-button`, `ArrowLeft` / `ArrowRight` step focus between buttons and `Home` / `End` jump to the first / last interactive button.

```html
<y-paginator total-pages="50" current-page="5"></y-paginator>
```

### y-data-grid
Interactive data grid for large datasets. Adds client-side or server-side sorting, filtering, and pagination on top of the visual language of `<y-table>`, plus row selection and inline cell editing. Use `<y-table>` for static reports; use `<y-data-grid>` for admin panels, CRMs, and any list users need to slice, page, select, or edit.

Tag: `<y-data-grid>`
Attributes:
- `columns` — JSON tree of column definitions. Leaves: `{"key": "name", "label": "Name", "type": "text", "sortable": true, "filterable": true, "editable": true, "editor": "text", "options": [...], "required": true, "min": 0, "max": 100, "pattern": "^...$", "width": "200px", "minWidth": 80, "resizable": true, "reorderable": true, "align": "left"}`. Groups (multi-column headers): `{"label": "Address", "align": "center", "children": [<leaf or group>, ...]}` — groups can nest arbitrarily, producing one extra header row per nesting level with the right `colspan`/`rowspan` so leaf headers extend to the bottom of the header. `sortable`, `filterable`, and `editable` default to true; set false to disable per column. `resizable` and `reorderable` also default to true but only take effect when `enable-column-resize` / `enable-column-reorder` are set on the grid; `width` is applied via a `<colgroup>`, and `minWidth` (px) clamps how far a column can be dragged smaller (default 48). `type` can be `"text"`, `"number"`, `"date"`, `"checkbox"` and drives both the filter and editor input type unless an explicit `editor` is given (one of `"text"`, `"number"`, `"date"`, `"select"`, `"checkbox"`). `options` is required for `select` editors. Validation: `required`, `min`/`max` (numbers), `pattern` (regex string).
- `data` — JSON array of row objects keyed by column `key`.
- `mode` — `"client"` (default) or `"server"`. In `client` mode sort/filter/page happen locally and edits mutate the local row. In `server` mode the grid passes data through unchanged and the parent must respond to `page-change`, `sort-change`, `filter-change`, and `cell-edit-end` events.
- `page-size` — rows per page (default `20`).
- `current-page` — 1-indexed current page (default `1`).
- `total-rows` — required in `server` mode for pagination math.
- `loading` — boolean; presents a loading state and sets `aria-busy`. What is shown depends on `loading-mode`.
- `loading-mode` — `"auto"` (default) | `"overlay"` | `"skeleton"`. `overlay` dims the body under a spinner (the pre-0.5.x behavior). `skeleton` always renders placeholder rows. `auto` renders skeleton when there are no rows to show and overlay when rows are already visible — so a first load shows shape-accurate placeholders while a refetch keeps the current data dimmed. The empty state never renders while `loading` is set, in any mode. Slot `skeleton` overrides the generated placeholder body; slot `loading` still overrides the overlay contents. CSS parts: `skeleton-body`, `skeleton-row`, `skeleton-cell`. Override `--component-data-grid-skeleton-row-height` to change placeholder row height (defaults to `row-height`).
- `skeleton-rows` — number of placeholder rows rendered in skeleton mode (default `page-size`, else `10`; clamped to a sane maximum).
- `striped` — boolean, defaults to false; add the `striped` attribute to enable alternating row backgrounds.
- `hover` — boolean, defaults to true; pass `hover="false"` to disable.
- `fixed-header` — boolean, defaults to true; sticky header on scroll.
- `filtering` — `"inline"` | `"advanced"` | (omitted). `"inline"` renders a per-column filter input row (uses `y-input`) beneath the header. `"advanced"` adds a funnel trigger to each leaf header that opens a filter popover (operator picker + value input + Clear/Apply buttons). Omitted (default) means no filtering UI — column filters can still be set programmatically via `el.filters = { ... }`.
- `enable-sorting` — boolean, defaults to true. Click a header to cycle asc → desc → none; shift-click to add a column to the multi-sort stack.
- `enable-pagination` — boolean, defaults to true.
- `show-item-count` — boolean, defaults to false. Adds a row count to the right edge of the footer. The paginator (when shown) stays on the left; both can be visible at once. Format: `"1–10 of 100"` when paginated, `"100 items"` when not, `"0 items"` when empty.
- `enable-selection` — boolean, renders a checkbox column (uses `y-checkbox`) and enables row selection (also via Ctrl/Cmd+click on the row).
- `enable-editing` — boolean, enables inline cell editing.
- `selection-mode` — `"multi"` (default) or `"single"`. In `single` mode the select-all header checkbox is hidden.
- `edit-on` — `"click"` (default) or `"focus"`.
- `row-key` — column key to use as the stable per-row identifier for selection and edit tracking. Falls back to the row's array index.
- `selected` — JSON array of row keys to mark selected (mirrored to the `selectedKeys` property).
- `empty-message` — fallback text when no rows are visible (default `"No data available"`).
- `row-height` — pixels per row (default `40`). Required for `virtual` mode; sets a fixed height on each row.
- `global-search` — string, search query applied across all column values.
- `group-by` — JSON array of column keys, e.g. `'["department","role"]'`. Renders collapsible group header rows; nested when multiple keys. Pagination is hidden while grouping is active.
- `aggregates` — JSON map of column key → aggregate kind (`"sum"` | `"avg"` | `"min"` | `"max"` | `"count"`). Aggregates render inside the group header row's column cells.
- `virtual` — boolean. When set alongside `viewport-height`, only the visible window + buffer is rendered. Pagination is hidden in virtual mode. Not compatible with `group-by`.
- `viewport-height` — pixels of scrollable viewport height (required for virtualization).
- `buffer-size` — extra rows rendered above and below the viewport (default `10`).
- `enable-header-menu` — boolean. Adds a kebab trigger to each leaf header that opens a column menu popover with sort ascending / sort descending / clear sort, a hover-opened "Columns" submenu (checkbox list to toggle column visibility — last visible column protected, changes staged until the submenu closes), and move-column-next / move-column-previous (within the leaf's sibling group when nested headers are used). Independent of `filtering`; combine `filtering="advanced"` with `enable-header-menu` to show both the funnel and kebab triggers. Filter operators (for `filtering="advanced"`): `contains`/`equals`/`startsWith`/`endsWith` for text, `equals`/`ne`/`gt`/`gte`/`lt`/`lte` for number, `equals`/`before`/`after` for date.
- `enable-column-resize` — boolean. Adds a drag handle on the inline (right) edge of each leaf header; drag to resize the column, double-click the handle to reset it to auto width. The new width is written to the grid's internal column tree (survives sort/filter/page/re-render) and emitted via `column-resize`. Opt out per column with `resizable: false`; clamp with `minWidth`.
- `enable-column-reorder` — boolean. Lets the user drag a leaf header onto another to change the column order; a drop line marks the insertion point and a plain (non-dragged) click still sorts. Reordering is constrained to the dragged column's sibling group when nested headers are used, mirrors the header-menu move actions, and emits `column-reorder`. Opt out per column with `reorderable: false`.

Slots: `header-before`, `header-after`, `footer-before`, `footer-after`, `empty`, `loading`, `pagination`.

Events:
- `page-change` (cancelable) — `{ page, pageSize }`. Cancel in `server` mode to suppress the local page update.
- `sort-change` (cancelable) — `{ column, direction, sorts }`. `sorts` is the full multi-sort stack.
- `filter-change` (cancelable) — `{ filters, operators, globalSearch }`. `operators` mirrors the per-column operator picked via the header menu.
- `row-select` (cancelable) — `{ rows, keys, event }`. Cancel to roll back the selection change.
- `cell-edit-start` — `{ row, column, value }`.
- `cell-edit-end` (cancelable) — `{ row, column, value, oldValue }`. Cancel to reject the commit and show the error state.
- `cell-edit-cancel` — `{ row, column, oldValue }`.
- `row-click`, `row-dblclick` — `{ row, event }`.
- `group-toggle` — `{ path, groupKey, expanded }`. Fires when a group header is clicked.
- `column-resize` — `{ column, width }`. Fires when a column is resized via its drag handle; `width` is the new pixel width, or `null` when reset to auto (double-click).
- `column-reorder` — `{ column, fromIndex, toIndex, order }`. Fires when a column is dropped in a new position; `order` is the full leaf-key order (including hidden columns).

Properties / methods: `selectedRows`, `selectedKeys`, `filters`, `sortState`, `groupBy`, `aggregates`, `clearFilters()`, `clearSort()`, `clearSelection()`, `selectRows(rows)`, `commitEdit()`, `cancelEdit()`, `expandGroup(path)`, `collapseGroup(path)`, `expandAllGroups()`, `collapseAllGroups()`, `refresh()`.

CSS parts: `grid-container`, `header`, `header-row`, `header-cell`, `body`, `row`, `cell`, `pagination`, `loading-overlay`, `empty-state`, `filter-input`, `filter-row`, `cell-editor`, `group-header`, `header-menu-trigger`, `header-filter-trigger`, `header-menu-popover`, `header-menu-submenu`, `header-filter-popover`, `column-resize-handle`.

CSS Custom Properties: `--component-data-grid-border`, `--component-data-grid-border-radius`, `--component-data-grid-border-width`, `--component-data-grid-border-width-header`, `--component-data-grid-padding-{small|medium|large}`, `--component-data-grid-row-height`, `--component-data-grid-row-height-{small|large}`, `--component-data-grid-row-stripe-bg`, `--component-data-grid-row-hover-bg`, `--component-data-grid-row-selected-bg`, `--component-data-grid-header-bg`, `--component-data-grid-header-hover-bg`, `--component-data-grid-header-text`, `--component-data-grid-filter-bg`, `--component-data-grid-edit-input-border`, `--component-data-grid-pagination-bg`, `--component-data-grid-loading-spinner-color`, `--component-data-grid-group-indent`, `--component-data-grid-scrollbar-width`, `--component-data-grid-resize-handle-color`, `--component-data-grid-drop-indicator-color`.

```html
<y-data-grid
  columns='[{"key":"name","label":"Name"},{"key":"age","label":"Age","type":"number"}]'
  data='[{"name":"Alice","age":30},{"name":"Bob","age":25}]'
  filtering="inline"
  page-size="10"
></y-data-grid>
```

### y-animate
Lightweight wrapper that applies a preset CSS-based entrance/exit animation to its children using the Web Animations API. Useful for adding visual polish to list items, modals, cards, or anything that enters / leaves the DOM.

Tag: `<y-animate>`
Attributes:
- `animation` — preset name: `"fade"` (default) | `"slide"` | `"zoom-in"` | `"zoom-out"` | `"flip-horizontal"` | `"flip-vertical"` | `"rotate-in"` | `"bounce"` | `"shake"` | `"scale"`
- `direction` — `"up"` (default) | `"down"` | `"left"` | `"right"`. Used by `slide`, `bounce`, and `shake`; ignored by `flip-*`, `zoom-*`, and `rotate-in`.
- `duration` — animation duration in ms (default `300`)
- `delay` — delay before the animation starts in ms (default `0`)
- `easing` — CSS easing keyword, `cubic-bezier(...)`, or `steps(...)` (default `"ease-out"`)
- `trigger` — `"load"` (default, plays on connect) | `"visible"` (plays when scrolled into view via `IntersectionObserver`) | `"manual"` (only via `play()`)
- `once` — `"true"` (default) | `"false"`. When false, visibility-based triggers re-fire on each entry.
- `reverse` — boolean, plays the animation in reverse
- `stagger` — boolean, animates each direct child individually with a per-index delay
- `stagger-delay` — per-child delay in ms when `stagger` is set (default `50`)
- `disabled` — boolean, blocks playback entirely
- `hidden` — standard HTML attribute; cancels any in-flight animation and hides the host

Events (bubble + composed, not cancelable):
- `animation-start` — `{ animation, element }` — fired when each animation begins
- `animation-end` — `{ animation, element }` — fired when each animation completes
- `animation-cancel` — `{ animation, element }` — fired when `abort()` is called or the host is hidden / disabled mid-flight

Methods:
- `play()` — manually triggers the animation. Returns `Promise<void>` that resolves once all animations finish.
- `reset()` — clears `hasPlayed` state and inline styles applied by stagger targets
- `abort()` — cancels any currently running animations and emits `animation-cancel`
- `setAnimation(name, duration?, easing?)` — convenience setter that updates the matching attributes

Slots: default — children to animate.
CSS Parts: `content` — the wrapper around the children.

Accessibility: respects `prefers-reduced-motion: reduce` — animations are skipped, but `animation-start` / `animation-end` still fire so consumers can sequence dependent UI.

CSS Custom Properties:
`--component-animate-duration` (default `300`), `--component-animate-stagger-delay` (default `50`), `--component-animate-fade-opacity-start` (default `0`), `--component-animate-fade-opacity-end` (default `1`), `--component-animate-slide-distance` (default `16px`), `--component-animate-zoom-in-scale-start` (default `0.8`), `--component-animate-zoom-out-scale-start` (default `1.2`), `--component-animate-rotate-angle` (default `90`), `--component-animate-bounce-height` (default `16px`), `--component-animate-shake-amplitude` (default `8px`), `--component-animate-scale-start` (default `0.5`), `--component-animate-scale-end` (default `1`).

```html
<!-- Fade in on mount -->
<y-animate animation="fade" duration="400">
  <y-card>Hello</y-card>
</y-animate>

<!-- Stagger a list when it scrolls into view -->
<y-animate trigger="visible" animation="slide" direction="up" stagger stagger-delay="80">
  <y-card>One</y-card>
  <y-card>Two</y-card>
  <y-card>Three</y-card>
</y-animate>

<!-- Manual play -->
<y-animate id="bump" trigger="manual" animation="bounce" once="false">
  <y-button>Bump me</y-button>
</y-animate>
<script>
  document.querySelector("#bump y-button").addEventListener("click", () =>
    document.getElementById("bump").play()
  );
</script>
```

## Icon Registry API

```javascript
import { registerIcon, registerIcons, getIcon, getIconNames } from "@waggylabs/yumekit";

// Register one icon (raw SVG string)
registerIcon("my-icon", `<svg viewBox="0 0 24 24">...</svg>`);

// Register many at once
registerIcons([
  { name: "icon-a", svg: `<svg>...</svg>` },
  { name: "icon-b", svg: `<svg>...</svg>` },
]);

// Retrieve
const svg = getIcon("my-icon");

// List every registered icon name (line names + `<name>-fill` variants)
const names = getIconNames();
```

`getIcon` returns the raw registered string. `<y-icon>` and `<y-rating>` render through the shared SVG sanitizer (see _SVG Sanitizer_ below), so script tags, event-handler attributes (`onload`, `onclick`, …), and any element outside the allowlist are stripped before the markup reaches the DOM — registering hostile SVG cannot lead to script execution through these components.

Pre-built icon categories (loaded via `import "@waggylabs/yumekit/icons/all.js"`):
- Arrows & chevrons (`arrow-up`, `arrow-down`, `arrow-left`, `arrow-right`, `chevron-up`, `chevron-down`, `chevron-left`, `chevron-right`, `expand-up`, `expand-down`, `expand-left`, `expand-right`, `ellipsis-v`, `ellipsis-h`)

## Public Modules

Published alongside the components and importable on their own. A component is not required to use them.

### Money (`@waggylabs/yumekit/modules/money.js`)

The currency rules behind `y-money`, as pure functions, for anything that **displays** an amount without collecting one — a ledger row, a running balance, a day total. An input is the wrong shape for those, and a second rounding rule is worse than an extra import.

The contract: an amount is an **integer number of minor units** plus a currency code, never a float. `12.34` has already lost the cent a balance is meant to reconcile, so a non-integer is rejected rather than rounded into a plausible-looking wrong number. Amounts reach `Intl` as decimal strings, so a balance past 2^53 stays exact; pass wide amounts as a string or `BigInt`.

- `formatMoney(value, options)` — integer minor units to a localized string. `formatMoney(-1234, { currency: "USD" })` → `"-$12.34"`. Returns `""` for anything that isn't integer minor units. Options: `currency` (default `USD`), `locale`, `display` (`symbol` | `narrowSymbol` | `code` | `name` | `none`), `sign` (`auto` | `always` | `never` | `accounting` | `parentheses`), `precision` (overrides the currency exponent). An unusable currency code drops the affix rather than the figure
- `currencyPrecision(currency, locale)` — the currency's minor-unit exponent (USD 2, JPY 0, KWD 3), read off `Intl` and cached; `2` for a code it can't resolve
- `toMinorUnits(value)` — canonical signed integer string, or `null` when the value isn't integer minor units. `"-0"` and `"0"` both canonicalize to `"0"`
- `minorUnitsToDecimal(minor, precision)` — `("-1234", 2)` → `"-12.34"`
- `decimalToMinorUnits(decimal, precision)` — the other direction, `("1234.56", 2)` → `"123456"`, rounding first
- `minorUnitsSign(value)` — `-1` debit, `1` credit, `0` zero, `null` when not an amount. Zero is its own answer; painting it as a credit asserts something
- `multiplyMinorUnits(value, quantity)` — an amount times a whole count, exact at any width, `null` when either side isn't whole. There is no rounding rule in it to get wrong
- `roundDecimal(decimal, precision)` — half-away-from-zero over digits, so `1.005` → `1.01`, not the float result. Scrubs grouping separators and symbols out of raw author strings
- `DEFAULT_CURRENCY` — `"USD"`

### Tokenizer (`@waggylabs/yumekit/modules/tokenizer.js`)

The syntax highlighter behind `y-code`, for anything that renders code a line at a time without embedding a whole `y-code` per line.

- `tokenize(language, source)` — `{ type, text }` tokens whose `type` values are Prism-compatible class names
- `isSupportedLanguage(language)` — whether a language (or alias) has a built-in tokenizer

## Helper Functions (internal, `src/modules/helpers.js`)

These are not exported in the public API but are used internally:

- `createElement(tag, attrs, children)` — single-call DOM builder used by every component to assemble its shadow tree without `innerHTML` (attributes flow through `setAttribute`, so user-controlled values cannot break out into new attributes or markup)
- `getColorVarPair(color, fallbackColor)` — resolves a color name to `[bg, fg]` CSS value pair. Predefined names return token `var()` pairs; hex/rgb/hsl values return the raw color with a WCAG-contrasted foreground via `contrastTextColor()`
- `isSafeCssColor(value)` — strict allowlist that returns `true` for `#hex` and the browser-native color functions (`rgb()`/`rgba()`, `hsl()`/`hsla()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()`); named colors, `var(...)`, `currentColor`, and nested functions are rejected. Components that paint a user-supplied color into a CSS context (`y-badge`'s `color`, `y-select`'s per-option `color`) gate the value through this helper and fall back to the semantic default when it fails
- `hideEmptySlotContainers(shadowRoot, config)` — hides wrappers when slots are empty
- `resolveCSSColor(varExpr, element)` — resolves CSS variable to computed color
- `manageLabelVisibility(labelWrapper)` — toggles label wrapper visibility on slotchange
- `parseColor(colorStr)` — parses hex/rgb to `{r, g, b}`
- `luminance({r,g,b})` — WCAG relative luminance
- `contrastTextColor(bgColor)` — returns `"#000"` or `"#fff"` for best contrast
- `clamp(v, min, max)` — clamp a number to a range
- `hsvToRgb(h, s, v)` — HSV → RGB (0-255)
- `rgbToHsv(r, g, b)` — RGB → HSV
- `hsvToHsl(h, s, v)` — HSV → HSL
- `hslToHsv(h, s, l)` — HSL → HSV
- `rgbToHex(r, g, b)` — RGB → hex string
- `rgbaToHex(r, g, b, a)` — RGBA → hex8 string
- `parseHexColor(hex)` — hex → `{r, g, b, a}`
- `parseColorString(str)` — any supported CSS color string → `{r, g, b, a}`

### SVG Sanitizer (internal, `src/modules/svg-sanitizer.js`)

Shared by `<y-icon>` and `<y-rating>` so both consume one allowlist-based sanitizer. Built-in icons are bundled and trusted; the sanitizer's job is to defend against script-bearing SVG passed through `registerIcon(name, svg)` at runtime.

- `sanitizeSvg(raw)` — parses an SVG string, strips every element and attribute outside the allowlist, and returns the resulting `outerHTML`. Empty input or markup with no `<svg>` root returns `""`
- `getSanitizedIcon(name)` — looks up a registered icon, sanitizes it, and memoizes the result. Repeated calls with the same name reuse the cached sanitized string
